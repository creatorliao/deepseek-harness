---

## 1. 你问的是什么

原话：充分考量费曼学习法；你学过这门技术；若把优秀学习法整合进技能，会如何调整、为什么；先出方案，等确认。

整理后：在**不推翻九场、不换讲解骨架**的前提下，让技能稳定走出「用自己的话教一遍 → 露出缺口 → 回仓库补 → 再讲得更短」这一环，而不是再发明第十套工作场景。

---

## 2. 费曼法在本仓里对应哪几步

经典四步，用本仓的话写：

| 费曼步 | 人在干什么 | 本技能里已经有的邻近场 |
|--------|------------|------------------------|
| 选定概念 | 这一次只讲一件事 | 九场都要求「一次主跑一个」 |
| 用简单的话教出来 | 讲给「没读过架构的人」 | S-learn-recall、S-train-lead、S-train-write |
| 卡住 = 缺口 | 某处不懂、或讲不下去 | S-learn-ask；工程师则 S-eng-deep |
| 再简化、再教一遍 | 更短、少行话 | 目前只有「能复述」，**没有强制第二遍** |

缺口：**教**和**补**是分开的场，但中间没有一条写死的「费曼环」。爱好者每次都要自己记得「讲完要回头找洞」，技能不会提醒，大脑又要适配。

所以要调的不是「再加一个费曼场景」，而是给**学习者三场 + 写成课**接上同一条环。工程师、产品场继续用同一套块顺序，只在该回头时点代号。

---

## 3. 为什么这样调（原理）

1. **费曼法是方法，不是工作情境。**
   「改装一处」和「网页用起来」是情境；「用自己的话讲、找洞、再讲」是在情境里怎么学。第十场 `S-feynman` 会和 `S-learn-recall` 抢同一件事，九场又变乱。

2. **你已经是爱好者，技能该替你省「记得用方法」这件事。**
   方法写进固定块，比写进又一篇鸡汤参考更稳：换角色也不换环。

3. **和「不知 → 知 → 做」同向。**
   费曼的「教」把「知」验成可出口的句子；卡住回到「不知」的精确点；再「做」最小一步（看一眼界面或读一个符号）。不另起学习哲学。

4. **能合并就合并。**
   初学者上手已并进 S-learn-use。费曼四步并进现有 recall / ask / write，不新增角色。

---

## 4. 建议改什么（确认后才动）

### 4.1 讲解骨架：第六块后面加「费曼环」（可选执行，场内必问）

九场块顺序保持：

图景 → 问题 → 步骤 → 边界 → 验收 → 下一步

在 **S-learn-use / S-learn-ask / S-learn-recall / S-train-write / S-train-lead** 五场，验收之后多问三句（对话和课文都要出现，短列表即可）：

1. **用自己的话**（假设听的人没读过 `architecture.md`）把本场概念讲一遍，禁止只复述命令名。
2. **卡壳点**写成缺口（哪一句讲不下去）。有缺口则下一步必须是 S-learn-ask 或 S-eng-deep，不许假装会了。
3. **第二遍更短**：补洞后再讲，目标比第一遍少一半行话。

S-eng-run / S-eng-change / S-eng-deep / S-prod-fit **不强制**三句（那是干活或取证）。但若用户明明在「想搞懂」，从深挖切到学习者费曼环，不要在工程师场里假装已经会教。

### 4.2 加厚三个学习者场（仍是三场，不拆第四场）

| 场 | 调整 |
|----|------|
| S-learn-use | 验收多一条：能用两句话说明「网页这张脸在干什么」，不是只会贴命令。 |
| S-learn-ask | 明确这是费曼的「找洞」：先让用户讲，再对准仓库事实补那一个洞。 |
| S-learn-recall | 升格为费曼主场：默认产出是「给假想初学者的口播稿」+ 缺口清单，不是默写步骤。 |

### 4.3 培训两场

| 场 | 调整 |
|----|------|
| S-train-write | 课文除 callout 外，须有一小节「用自己的话」（给没读过架构的人）。这就是费曼的书面版。 |
| S-train-lead | 带人时让对方讲，你只勾缺口；不要自己讲满。 |

## 6. 不采用的做法（以及原因）

| 做法 | 为何不采用 |
|------|------------|
| 第十场 `S-feynman` | 与 recall/write 重叠，角色轴又斜切一刀 |
| 把九场改成「费曼四步」四个场景 | 工程师改装、产品边界不是「教一遍」能覆盖的情境 |
| 只在 L05 写一段费曼介绍、工作流不改 | 爱好者仍要靠记忆触发，技能行为不会变稳 |
| 每场都强制口播两遍 | 改装/排错被学习仪式拖死；只绑在学习与教学场 |

---

## 7. 确认后怎么验收

- 用户说「这段没懂」→ 走 S-learn-ask，先听他讲再补洞。
- 用户说「我学过，帮我费曼一下」→ 走 S-learn-recall，先口播，再缺口，再缩短。
- 用户说「写教程」→ S-train-write，文内有「用自己的话」。
- 用户说「改装这处」→ 仍是 S-eng-change，不插入口播两遍。
