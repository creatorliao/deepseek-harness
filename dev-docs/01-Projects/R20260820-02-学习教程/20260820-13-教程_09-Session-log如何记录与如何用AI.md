# 课 09 · Session log 如何记录、怎么用、AI 能不能改行为

> [!abstract] 一句话
> 事件只追加、模型看见的必须能从 log 重建；导出给人或测试 replay，默认网页不会让模型读 ZIP 并自动改程序。

## 图景

一次对话不是「数据库里改一行聊天」。运行时往 `Session` 上 **append** 带类型的事件；内存里的 `ctx.sessions` 是正在写的那本账；插件订阅 `session/event`，异步写到 `~\.dsh\sessions\…\session.jsonl.zstd`。界面、轨迹、发给模型的 messages，都是事后从同一本账**折**出来的。

所以：你在网页上删不掉「刚才模型其实看见了技能清单」——那一截已经是 `user/message`。你也没法靠导出把账本搬走：ZIP 只是抄本。

```text
用户/工具/插件  →  Session.append  →  内存事件流
                         ↓
              session/event + flush
                         ↓
              ~/.dsh/sessions/…/session.jsonl.zstd
                         ↓
         对话气泡 / 轨迹表 / deriveMessages() / ZIP 导出 / resume
```

## 步骤

### 1. 它是怎么记进去的（仓内路径）

| 环节 | 核对 |
|------|------|
| 内存真源 | `packages/core/session`：`Session.append()`；LLM 历史用 `deriveMessages()` 派生，不另存一份 |
| 落盘 | `packages/session/session-persistence-jsonl`：默认 zstd；连续的 `assistant/chunk` 可打成 packed 行（导出 ZIP 里仍是逻辑 jsonl 文本） |
| 根目录 | `packages/bundle/base/cordis.patch.yml`：`root: !!js dshHomePath('sessions')` |
| 网页导出 | `GET /api/session.export` → `sessionLogZipEntries()` / `readRaw()`；先对活动根会话 `flush` |
| 按钮与 `/export` | `packages/session-query/session-log-export` |

`seq` 必须连续。中间抽掉 chunk「好看一点」会破坏规范 log。后端可以自己编码存储，但 `load` 必须还原成当初那串事件。

### 2. 记录了什么：先认几族事件

完整目录在 [docs/persistence-catalog.md](../../../docs/persistence-catalog.md)。课里只记读样板够用的族：

| 族 | 例子 | 读的时候看什么 |
|----|------|----------------|
| 会话头 | 第一行 `type: session` | id、cwd、preset |
| 策略 | `permission/preset`、`sandbox/mode`、`approval/policy` | 当时允许多大胆 |
| 轮次括号 | `turn/start`、`step/start`、对应的 `end` | 第几轮、第几步 |
| 模型可见输入 | `user/message`、`request/header`、`request/context` | 人说的 + 插件注入的 + 模型名 |
| 模型输出 | `assistant/chunk`（以及后来折成的 assistant 消息） | 吐字、工具意向、**失败 finish** |
| 工具 | `tool/call`、`tool/result` | 名字、参数、结果 |
| 用户命令 | `command/run`、`command/done` | `/permission`、`/export` 等 |
| 标题 | `session/title`、`session/title-llm-request` | 侧边栏标题怎么来的 |

「轨迹」把其中一部分摊成表；**不是**另一份存储。

### 3. 对照同一份样板（事件名版）

文件仍是课 08 那份 `session.jsonl`，不整份粘贴。

| `seq` 附近 | `type` | 解读 |
|------------|--------|------|
| header | `session` | 工作区 `hermes-agent-setup`，预设 `standard` |
| 0–2 | 三个策略事件 | 先 `workspace-write` + `ask` |
| 3–9 | inbox → `turn/start` → 多条 `user/message` | 你的「目录里面有什么嘛，」以及系统/技能快照 |
| 11–12 | `request/header`、`request/context` | `deepseek-v4-flash`，上下文窗口数字 |
| 14–16 | `assistant/chunk` finish `AUTH` → `turn/end` | 第一轮因 Key 无效结束；Key 已打码 |
| 18–23 | `command/run` `permission` → 策略改 `danger-full-access` / `never` → `command/done` | 你改权限，模型没自己改 |
| 25+ | 新 turn「你是谁？」 | 正常循环 |
| 285 | `tool/call` `pwsh` | 列目录；参数在 `data.arguments` 字符串里 |

读失败时优先搜 `"kind":"error"` 或 `"code":"AUTH"`，不要从对话气泡反推。

### 4. 官方为什么要设计它

**仓内事实（架构 + Agent Note）：**

1. **一本账。** 续聊、分叉、抄本、遥测、落盘都从同一 append-only 流来，避免「界面一套、模型一套、磁盘又一套」。
2. **模型可见 ⟺ 已记录。** 新能力如果只偷偷塞进请求、不写 event，resume / replay / 测试会对不上。所以新模型可见输入 = 新 `SessionEventMap` 成员。
3. **导出给人或 bug 单。** 轨迹不够：折叠过、缺子代理整树、不是原始字节。ZIP 用 `readRaw`，保留打包行和换行，不在浏览器里重压 23 MB 级会话。

`/export` 本身**故意**不进模型历史：下载是人的副作用，不是又一轮上下文。

细节与外链见 [调查报告](../../03-Resources/20260820-04-调查报告_Session-log官方与社区.md)。

### 5. 官方工程师怎么用

公开仓库能核对到的，是**测试与冷读**，不是「把 ZIP 丢回聊天」：

- `pnpm run test:snapshot`：用录好的 `session.jsonl` 回放 LLM 流，无 Key 也能回归界面 / ACP 期望。
- `@deepseek-ai/dsh-llm-replay`：`parseSessionLog` / `deriveReplayScript`。
- `sessionQuery.readSession(id)`：脱离 live，replay 校验完整 log。
- `resume` / `fork`：从磁盘账本继续或截前缀开新会话。

这就是「改善程序行为」在官方流程里的位置：先让行为可复现，再改插件或测例，而不是让线上模型改自己的源码。

### 6. 社区怎么用（标成社区）

- [Discussion #1473](https://github.com/deepseek-ai/deepseek-harness/discussions/1473)：一份坏的 zstd 头曾让整个网页起不来。后来 `list()` 会跳过坏工件；那一份会话仍可能打不开。
- [dsh-doctor](https://github.com/boyin111-1/dsh-doctor)：第三方。`--session` 扫 `seq` 缺口和悬挂 tool_call。**不是**本仓命令。
- 外评文章复述「append-only + model-visible means logged」，没有另一套产品定义。

公开讨论里，社区主业是**排障**，不是「用 log 自动调参」。

### 7. 能不能让 AI 自己分析、自己改善行为

分四条路，不要揉成一句「能」或「不能」。

| 路 | 现在有没有 | 改善的是什么 | 不是什么 |
|----|------------|--------------|----------|
| **A. 同一会话 resume** | 有。侧边栏再打开 | 模型带着**已派生的历史**继续聊 | 它没有去「读文件」；看不见你 Downloads 里的 ZIP |
| **B. 测试 replay** | 有。给开发者 / CI | 固定行为，防止你改插件改崩 | 不在用户网页里跑 |
| **C. 模型查询工具** | 包存在：`session_search` 等 | 经工作区授权搜**其它会话**的标题/事件 | **默认网页不挂** `dsh-tool-session-query`。要挂是改装（`S-eng-change`），且跨会话要求 `cwd` 严格相同 |
| **D. 把 ZIP / jsonl 交给另一个 AI**（例如 Cursor） | 人可以做 | 人读结论，人改代码或提示 | 不是 DSH 产品闭环；把敏感 log 交给第三方等于泄露工作区与技能清单 |

**没有的开箱能力：**

- 网页智能体自动打开你刚下载的 ZIP，当成 RAG 再改自己的策略。
- `/export` 触发一轮「请分析我并改进」。
- `cordis_inspect` / `cordis_mount`（创造模式那套）改的是**当场运行时插件树**；resume **不会**重建临时 mount。那是改 live 组装，不是读历史 jsonl。
- Compaction 用 log 里的摘要减轻 token，不是「分析后改产品」。

若你的目标是「让网页里的同一个 Agent 少犯同样的错」：先把错钉在 log 里（课 08 那种 AUTH / 工具参数），再由**人**改 Key、改预设、改插件或改工作区规则。不要把整份 log 贴回对话框。

## 边界

- 手改 jsonl 中间行极易制造 `seq` 缺口；加载器会认为 corrupt。先**整目录复制**再试第三方医生或删掉坏会话目录。
- 不要用记事本把 zstd 当文本打开去「修」。导出 ZIP 里的明文 jsonl 才适合人读。
- 密钥打码 ≠ 可以公开。工具参数里可能有路径、文件片段。
- 本课不把 `tool-session-query` 说成已经装在本仓网页上。
- 不要把 Key 贴进对话「让 AI 修 AUTH」。

你带别人时：同一张验收，先课 08 勾完，再让对方用自己的话讲清表「四条路」。
