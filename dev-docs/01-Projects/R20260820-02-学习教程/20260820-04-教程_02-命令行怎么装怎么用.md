## 1. 「命令行工具」装的是哪一个

命令行工具就是 **`dsh` 这个启动器**。它本身几乎不干活，只负责：看你要哪个 **profile**，把对应插件组合起来，再把后面的参数交给那个组合。

| 你在哪 | 怎么调用 |
|--------|----------|
| 本仓库根目录（路 B） | `pnpm dsh …`（走源码入口，一般不必先 `build`） |
| 已经全局/npx 装了发布包（路 A） | `npx @deepseek-ai/dsh …` 或安装后的 `dsh …` |

本课默认你在**仓库根**，且课 01 的 `pnpm dsh --help` 已经通过。

**profile** 可以先记三件事：

- `dsh web` = 启动网页那一套（下一课）。
- `dsh --profile headless "一句话任务"` = 不开浏览器，跑完打印答案就退出。
- 工作目录很重要：你在哪个文件夹执行命令，那个文件夹就是默认项目根。

`web` 和 `headless` 第一次用时会自动从模板建好。其它名字的 profile 要先用 `dsh plugin` 创建，初学可以不管。

---

## 2. 先看帮助，不要背参数

启动器自己的帮助：

```sh
pnpm dsh --help
```

网页应用自己的帮助（不会真的开服务器）：

```sh
pnpm dsh web --help
```

规则：**启动器认识的开关写在最前面**；它不认识的第一个词开始，都交给当前 profile。

```sh
pnpm dsh --profile web --port 8080
```

这里 `--port` 属于网页应用，不是启动器。

完整 flag 表：[CLI 行为参考](../../../apps/cli/reference/README.zh.md)。初学只记 `--help`、`web`、`--profile headless`。

## 3. 第一条无界面任务

在**你想让 Agent 看到的那个项目目录**里执行（本仓根也可以）：

```sh
pnpm dsh --profile headless "用三句话介绍这个仓库是干什么的"
```

成功时：标准输出里是最后一段助手文字，退出码 0。
失败时：退出码非 0（常见原因是没密钥、或模型拒绝）。

headless **不会**开端口、也不会开浏览器。

没有 `DEEPSEEK_API_KEY` 时这条会失败。把密钥放到根目录 `.env`：

```sh
DEEPSEEK_API_KEY=sk-你的密钥
```

可选：`DEEPSEEK_BASE_URL=https://...`（一般不用）。**不要把 `.env` 提交进 Git。**

## 4. 日常还会碰到的几条

```sh
# 启动网页（课 03）
pnpm dsh web

# 只起服务、不自动开浏览器
pnpm dsh web --no-open

# 不启动，只打印「拼出来的配置」给排查用
pnpm dsh --profile web --dump-config
```

给某个 profile 加减插件（进阶）：

```sh
pnpm dsh plugin --profile 某个名字 add 某个包
```

初学可以跳过。改完插件要**重新启动**该 profile 才生效。

## 5. 和网页怎么选

| 你想 | 用 |
|------|----|
| 点一点、看对话、审批工具 | 网页（课 03） |
| 脚本里跑完就退出、CI、只要最终答案 | `headless` |
| 人在终端里多轮聊 | 官方以后可能有 TUI 类 profile；本仓入门先用网页 |
