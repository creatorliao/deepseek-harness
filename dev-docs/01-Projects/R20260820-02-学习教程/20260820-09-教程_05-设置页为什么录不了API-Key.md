# 课 05 · 为什么设置里录不了 API Key，文件又在哪

> [!abstract] 一句话
> 「模型」页灰掉并写「由启动环境提供（只读）」是启动时已经有钥匙，不是输入框坏了；Windows 面板空着，钥匙往往在 Git Bash 的 `~/.bashrc`。

> [!question] 这一课要解决的问题
> 作为本仓库**源码启动**的网页用户：设置里「通用设置」没有 Key 框；切到「模型」后 DeepSeek 的「API 密钥」被 disable，占位是「由启动环境提供（只读）」。为什么灰掉、为什么 Windows「环境变量」里仍搜不到、配置文件与明文各在哪、若只想用网页要不要解锁。学完能判断「灰掉 = 已有启动钥匙」，并知道解锁必须改启动环境后重启服务。当前不改产品界面。
>
> **原始提问**
> 请你帮我创建一个教程为什么我在界面上没办法录入那个 api key?我希望在那个界面就可以录入api key。我作为一个普通的用户，然后的话，通过代码。启动了这一个项目，在网页上面执行的时候，根本就没办法录入api key 我也没有在我的环境变量里面找到对应api key，为什么呢？另外我想知道它的配置文件存到哪里了，比如说我填入api key，存在哪里了？
>

> 这真是个非常有趣的发现，请你帮我把这个发现记录到刚才的文档里，把这个问题记录进去，把根本原因也记录进去，我已经清空bashrc的内容，请你帮我重新启动服务，我希望进去再试一遍。

## 发现记录（本机 · 2026-08-20）

这一节是现场对上的事实，不是猜测。密钥正文不进文档。

### 问题

源码启动网页后，普通用户想在设置里录入 API Key。Windows「环境变量」面板里找不到 `DEEPSEEK_API_KEY`。先进「通用设置」没有框；再进「模型 → DeepSeek」，「API 密钥」被 disable，占位 **「由启动环境提供（只读）」**。

### 现象（对照截图）

| 观察 | 事实 |
|------|------|
| 通用设置 | 只有预设、权限、语言、外观、Enter；没有密钥框 |
| 模型页输入框 | `disabled`，文案「由启动环境提供（只读）」 |
| Windows 用户 / 系统环境变量 | **没有**这个名字 |
| 仓库根 `.env`、`~\.dsh\.env`、`~\.dsh\.credentials.yaml` | 当时都不存在 |
| `~\.dsh\settings.yaml` | 存在，且不含明文 Key |
| 启动网页的 Git Bash | 读了 `C:\Users\creator\.bashrc`，当时文件里有 `DEEPSEEK_API_KEY` |
| 当前 Cursor / Bash 会话 | 即使后来清空 `.bashrc`，**进程里仍可能带着旧值**（环境在启动时冻结） |

### 根本原因

产品把凭据分成几层。只有 **「继承的进程环境」** 会把网页输入锁成只读。

实现落在 `packages/credentials/credentials-local`：`describe()` 若在启动快照的 `process` 层看到非空的 `DEEPSEEK_API_KEY`，就报告 `source: 'env', writable: false`。`packages/client/ui-settings-models` 的编辑器读到 `writable === false`，就把输入框 `disabled`，占位换成「由启动环境提供（只读）」。

Git Bash 会执行 `~/.bashrc`。里面的 `export DEEPSEEK_API_KEY=…` **不会**写进 Windows 系统属性面板，但会进这个 Bash（以及从它拉起的 `pnpm dsh web`）的进程环境。于是出现「面板是空的、网页却只读」——两套「环境」不是同一个地方。

网页「保存」只写 `~\.dsh\.credentials.yaml`，并且**故意不把**这份文件灌进 `process.env`。所以：

- 钥匙在 `.bashrc` → 界面只读，磁盘上可以没有 `.credentials.yaml`。
- 钥匙只在凭据文件里 → 界面可改，Windows 面板仍然可以是空的。

清空 `.bashrc` **不够**：已经跑着的 `dsh web` 和已经打开的终端，还记着旧环境。必须停服务，并在一个**没有**该变量的新进程里再启动。

### 结论（给下次的自己）

1. disable ≠ 坏了；= 启动进程已经有钥匙。
2. 别只在 Windows 面板里找；Windows 上先看 Git Bash 的 `~/.bashrc`。
3. 要在网页里自己贴 Key：去掉进程环境里的该变量，再重启服务，然后「设置 → 模型」应能打字。

## 图景

设置对话框左边是四个**分区**，不是四个按钮重复同一张表。

你截图里左侧高亮的是 **「通用设置」**。这一页管的是：默认 Agent 预设、新会话权限、界面语言、浅色/深色、忙的时候按 Enter 是排队还是别的。**这里从来没有 API Key 输入框。** 不是源码启动坏了，也不是密钥丢了。

密钥属于 **「模型」** 分区。产品把「怎么用页面」和「用哪家模型、用哪把钥匙」拆开了。希望「就在通用设置那一页也能贴 Key」是合理的产品愿望；**当前仓库没有这个框**，改界面要另开改装场，本课只教你用现成入口。

## 步骤

### 1. 对照你这张图：先认页

打开设置后看左侧，不要先点右上角。

| 左侧 | 这一页管什么 | 有没有密钥框 |
|------|----------------|--------------|
| **通用设置**（你现在在这） | 预设、权限、语言、外观、Enter | 没有 |
| **模型** | 各提供方的 API 密钥、地址、模型目录 | **有** |
| 插件 | 扩展开关与清单 | 没有 |
| Agent 预设 | 预设本身 | 没有 |

右上角 **「打开配置文件」** 属于通用设置这一套：它打开的是 **设置文档**（默认 `settings.yaml`），不是密钥本。点它不能用来「在记事本里填 Key 就当保存成功」。

### 2. 到「模型」页：先看框是不是灰的

1. 左侧点 **「模型」**（英文界面是 Models）。
2. 打开 **DeepSeek** 那一张卡片。
3. 看 **「API 密钥」** 框，分两种：

| 框的样子 | 含义 | 你要不要再贴 |
|----------|------|----------------|
| 能打字，占位「输入 API 密钥」或「已配置——输入新值可替换」 | 网页可以写凭据文件 | 没有钥匙就贴；已配置可换 |
| **灰掉**，占位 **「由启动环境提供（只读）」** | 启动 `dsh web` 的那个进程里**已经有** `DEEPSEEK_API_KEY` | **不用再贴。** 对话可以用这把钥匙。网页故意不让你改，免得你以为改了其实还是环境说了算 |

灰掉不是坏了，也不是「打开配置文件」弄的。点保存也改不了这一格。

现场数字与路径见上文「发现记录」。**不要**把 `.bashrc` 或凭据文件里的密钥贴进对话或 Git。

若框是空的、能打字：从 [DeepSeek 开放平台](https://platform.deepseek.com/) 复制 `sk-` 密钥（不要加引号，不要写成 `DEEPSEEK_API_KEY=sk-…`），点 **「保存」**。成功后徽标变成「API 密钥已配置」，明文不再显示。

第一次弹窗 **「添加一个 API Key 开始使用」** 与这一页是同一条通道。点过 **「稍后配置」** 且启动环境也没有钥匙时，必须来这里补。

### 3. 看两份文件各管什么

本机默认家目录叫 **harness home**：环境变量 `DSH_HOME` 若没设，就是用户目录下的 `.dsh`。

Windows 上通常是：

```text
C:\Users\<你的用户名>\.dsh\
```

| 文件 | 点「打开配置文件」会不会开它 | 里面有没有明文 Key |
|------|------------------------------|---------------------|
| `C:\Users\<你的用户名>\.dsh\settings.yaml` | **会**（通用设置那个按钮） | **没有。** 只有外观、语言、提供方段落，以及凭据**名字**（例如引用 `DEEPSEEK_API_KEY`） |
| `C:\Users\<你的用户名>\.dsh\.credentials.yaml` | **不会** | **有。** 网页「保存」后，明文写在这里 |

`.credentials.yaml` 长得像一张名字到值的表，例如：

```yaml
DEEPSEEK_API_KEY: sk-…
```

`settings.yaml` 里出现 `DEEPSEEK_API_KEY` 四个字，只表示「去凭据库里取这个名字」，**不是**操作系统已经 export 了这个变量。

不要把整个 `.dsh` 拷进 Git，也不要把这两份文件贴进对话。

### 4. 为什么 Windows 环境变量里找不到，框却是只读

产品认的是 **启动 `dsh web` 那一瞬间进程里的值**，不是「系统属性 → 环境变量」那一块面板。

常见三层，优先级从高到低：

1. **继承的进程环境**（只读）。Git Bash 读了 `~/.bashrc` 里的 `export DEEPSEEK_API_KEY=…`、PowerShell 配置文件、或你在启动前手工 `set`，都属于这一层。界面灰掉。
2. **`$DSH_HOME/.credentials.yaml`**（网页「保存」写这里，可改）。
3. **仓库根 `.env` 或 `~\.dsh\.env`**（后备；界面仍可保存来盖过它们）。

所以会出现这种组合：**面板是空的 + 模型页是只读**。钥匙在 Bash 配置里，不在 Windows 用户环境里。

网页保存**不会**往 Windows 面板加一行，也**不会**把 `.credentials.yaml` 灌进 `process.env`。

### 5. 若你坚持要在网页里改钥匙

只在你要**换一把**、而且不想用 `.bashrc` 里那把时才做：

1. 编辑 `C:\Users\creator\.bashrc`，把含 `DEEPSEEK_API_KEY` 的那一行注释掉或删掉。
2. 停掉正在跑的 `dsh web`（终端 `Ctrl+C`）。
3. **关掉这个 Git Bash 窗口**，再开一个新的（旧窗口还记着旧环境）。
4. 再 `pnpm dsh web`。此时框应能打字，保存会写出 `~\.dsh\.credentials.yaml`。

环境层在启动时冻结：只改文件、不重启服务，框不会变。

### 6. 你自己用：最小对照

框若是只读：关掉设置，选中工作区，发一条只读任务即可，不必找 `.credentials.yaml`。

框若刚保存过：资源管理器打开 `C:\Users\<你的用户名>\.dsh\`，打开「隐藏的项目」，应能看到 `.credentials.yaml`。不要把文件内容发到聊天。

### 7. 你讲给别人时

先让对方指认左侧是不是停在「通用设置」，再让对方看「模型」框是能打字还是灰掉只读。灰掉就说「启动环境已经有钥匙，可以直接对话」。不要一上来讲 YAML。不要让对方把 `.bashrc` 里的密钥贴出来。

## 边界

- **当前不能**在「通用设置」页录入 API Key。本课不改代码、不加输入框。若要改产品，下一场是工程师改装（`S-eng-change`），先归档再动叠加层。
- 「打开配置文件」打开 `settings.yaml`。手改高级字段可以，但**不要把 `sk-` 明文写进这份设置文档**当密钥存储；网页保存路径是 `.credentials.yaml`。
- 若「模型」页显示「由启动环境提供（只读）」，钥匙已经够用；网页改不了。要换钥匙先改启动环境（本机常见是 `~/.bashrc`），再**新开终端并重启** `dsh web`。
- 「打开配置文件」仍然只开 `settings.yaml`，解不开这把只读锁。
- 若「模型」页提示当前部署的设置文档为只读，那是部署策略，不是你找错页。
- 服务只监听本机回环。不要为了「好填 Key」把页面暴露到公网。
- 本课不讲命令行 `export` / `pnpm dsh --profile headless`。
