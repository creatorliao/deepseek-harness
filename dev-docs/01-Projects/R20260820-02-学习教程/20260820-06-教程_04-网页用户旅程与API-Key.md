# 课 04 · 网页用户旅程：启动、填 API Key、注意事项

> [!abstract] 一句话
> 先点「继续」看完内测声明，在弹窗或「设置 → 模型」保存 API Key，再选中工作区才能对话。

> [!question] 这一课要解决的问题
> 网页打开后按什么顺序填 Key、选工作区、发任务；用户必须守住哪些红线。
>
> **原始提问**
> 我作为一个用户，我应该如何填入 apik？应该注意哪一些事项？

## 0. 旅程总览

```text
启动 dsh web
  → 浏览器打开 http://127.0.0.1:3080
  → （首次）内测声明：点「继续」
  → （还没密钥）弹窗「添加一个 API Key 开始使用」
  → 选工作区（不选则不能打字）
  → 新建会话，发第一条任务
  → 工具要改文件或跑命令时，先审批再继续
```

密钥也可以跳过弹窗，之后在 **设置 → 模型** 里补。

---

## 1. 把入口界面启动起来

### 发布版（没有本仓库）

```sh
npx @deepseek-ai/dsh web
```

### 本仓库源码（你现在这条）

网页不是 `pnpm install` 完就能开。生产组合要已构建的包和 `apps/web/dist`。没构建时，启动会直接失败，类似：`frontend dist not built; run pnpm run build`。

在仓库**根目录**：

```sh
pnpm run build
pnpm dsh web
```

`build` 第一次可能要好几分钟。成功后默认：

| 项 | 值 |
|----|-----|
| 地址 | `http://127.0.0.1:3080` |
| 本机 | 一般会自动打开浏览器 |
| 不要自动开浏览器 | `pnpm dsh web --no-open`，自己打开上面的地址 |
| 换端口 | `pnpm dsh web --port 3081`（`--port` 写在 `web` 后面） |

不要加 `--host 0.0.0.0`：当前命令行会当成用法错误。服务只给本机回环地址，这是有意的。

停服务：跑 `dsh web` 的那个终端按 `Ctrl+C`。

## 2. 第一次打开页面：两道门

### 门 A：内测声明

标题是 **「内测声明」**。说明当前是 0.1、面向开发者测试、接口还会变。读完点 **「继续」**。

这只记「我看过这版声明」，**不会**替你保存 API Key。

### 门 B：还没有可用模型时

若本机还没有任何能对话的提供方，会再出一道对话框：

- 标题：**「添加一个 API Key 开始使用」**
- 说明：**「配置 DeepSeek 官方模型，即可开始使用。」**
- 输入框标签：**「API key」**（占位：**「Enter your API key」** / 中文环境以页面为准）
- 主按钮：**「保存并继续」**
- 次按钮：**「稍后配置」**

**推荐：在这里填。** 从 [DeepSeek 开放平台](https://platform.deepseek.com/) 复制密钥，粘贴进去，点「保存并继续」。

- 密钥一般以 `sk-` 开头。不要加引号、不要前后空格（界面通常会去掉空格，但不要自己加花括号或「API_KEY=」前缀）。
- 保存成功后，页面**再也看不到明文**，只会显示类似「已配置」的状态。这是设计，不是丢了。
- **不用重启** `dsh web`。下一轮请求就会用新密钥。
- 点「稍后配置」可以进主界面，但发任务仍会失败，直到你走第 3 节补上。

若启动环境已经提供了只读的 `DEEPSEEK_API_KEY`（例如仓库根 `.env` 被启动器读到），输入框可能显示只读「由启动环境提供」。那种情况不必再贴一遍。

---

## 3. 过后补密钥：设置 → 模型

1. 点侧边或顶栏的 **「设置」**。
2. 左侧进 **「模型」**（英文界面是 Models）。
3. 页头大意是：给下列提供方填 API 密钥才能用模型。
4. 打开 **DeepSeek** 那一张卡片。
5. 在 **「API key」** 框粘贴密钥。
6. 点 **「应用」**（保存中会显示「应用中…」）。

成功提示类似「已保存 …」。徽标会从「缺少 API key」变成「已配置 API key」。

其它厂商或公司网关：用「添加提供方」/「添加自定义提供方」。初学只用官方 DeepSeek。细则见 [配置模型](../../../docs/user/guide/providers.zh.md)。

密钥落在本机用户目录，默认是 **`~/.dsh/.credentials.yaml`**（Windows 即 `C:\Users\你的用户名\.dsh\.credentials.yaml`）。设置文件是 `~/.dsh/settings.yaml`，里面只有凭据**引用**，没有明文。不要把 `.dsh` 拷进 Git，也不要发到聊天里。

---

## 4. 选工作区，才能打字

全新网页**不会**自动选中文件夹。没选中工作区时，会话输入框不可用。

1. 找到 **「工作区」** / **「添加工作区」**。
2. 选一个你允许 Agent 读写的项目文件夹（可以就是本仓库，也可以是别的练习目录）。
3. **选中**它（只添加、不选中，仍然不能发消息）。

`dsh` 是从哪个目录启动的，那个目录只是默认文件系统位置；界面里仍要你点一次选中。

---

## 5. 第一条任务

新建会话，用中文即可，例如：

> 用三句话说明当前工作区是做什么的，先不要改任何文件。

Agent 可以读文件、改文件、跑终端命令。需要你批准时，页面会先问。**先看它要改什么、跑什么，再点同意。**

想少出事：第一条任务写明「只读、不要改文件」；练习目录不要指向存有密钥或私人照片的盘。

---

## 6. 作为用户要注意什么

| 事项 | 为什么 |
|------|--------|
| 密钥只进设置弹窗或「设置 → 模型」，不要发进对话 | 对话会进会话日志，可能被复盘、同步、截图 |
| 不要把 `~/.dsh`、`.env`、密钥提交到 Git 或发给别人 | 别人拿到就能花你的额度、读你的项目 |
| 保存后看不到明文是正常的 | 只写存储；丢了就重新贴一条 |
| 不必为换密钥重启网页服务 | 模型配置下次请求生效 |
| 必须先选工作区 | 否则输入框是死的，不是坏了 |
| Agent 默认会动你选中的目录 | 写文件、跑命令都可能发生；审批不要闭眼点 |
| 产品仍是开发者预览 | 升级可能不兼容旧配置；内测声明说的就是这件事 |
| 服务只监听 127.0.0.1 | 不要想办法把页面暴露到公网再贴密钥 |
| 本仓库源码必须先 `pnpm run build` | 没产物时入口起不来；改了前端也要再 build 并**刷新原标签页** |
| 不要另开一个端口验旧页面 | 容易改的是 A、看的是 B |
| 密钥无效、欠费、网络不通 | 界面能开、任务会失败；先回「设置 → 模型」看是否仍显示已配置 |
| 额度与费用 | 走 DeepSeek 账单，与本仓库无关 |

---

## 本课验收

- [ ] 浏览器能打开本机 Web 入口（默认 3080）
- [ ] 已用弹窗或「设置 → 模型」保存过 DeepSeek API Key（或能解释只读环境密钥）
- [ ] 已选中一个工作区，输入框可点
- [ ] 知道密钥在本机 `~/.dsh`，不会写进仓库
- [ ] 知道 Agent 可能改文件，审批要看内容
