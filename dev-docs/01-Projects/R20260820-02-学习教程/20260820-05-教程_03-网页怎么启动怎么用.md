## 1. 启动：两条命令，一个界面

网页不是另装一个软件。还是 `dsh`，只是启动了名叫 `web` 的 profile。`dsh web` 就是 `--profile web` 的别名。

### 路 A：发布版（没有本仓库也行）

```sh
npx @deepseek-ai/dsh web
```

### 路 B：本仓库源码

官方完整路径（有前端构建产物）：

```sh
pnpm install
pnpm run build
pnpm dsh web
```

`pnpm dsh web` 会用**已经构建好的**网页产物，自己不会再编一次。若页面空白或资源 404，回到根目录再跑一次 `pnpm run build`。

只想先把服务拉起来、接受可能不完整的前端时，仍可先 `pnpm dsh web`；要以官方「从源码运行」为准时，请带上 `build`。

本机启动成功后：

- 默认地址：`http://127.0.0.1:3080`
- 一般会自动打开系统浏览器
- 终端里会打一行英文：`dsh web: opening the default browser; pass --no-open to disable`

不想自动开浏览器：

```sh
pnpm dsh web --no-open
```

然后自己打开上面的地址。

换端口（`--port` 必须写在 `web` 后面）：

```sh
pnpm dsh web --port 3081
```

不要用 `--host 0.0.0.0`：当前 CLI 会当成用法错误退出。网页默认只绑本机回环地址。

通过 SSH 远程跑时，命令通常**不会**帮你开本地浏览器，只打印服务器上的 URL；本地怎么转发端口，由你的 SSH 客户端负责。

停服务：在跑 `dsh web` 的那个终端按 `Ctrl+C`。第一次是优雅退出；卡死再按一次会强制退出。

## 2. 打开页面之后：三步才能对话

官方指南从「服务器已经在跑」开始。按这个顺序，少踩坑。

### 第一步：配置模型

打开 **设置 → 模型**。在 DeepSeek 卡片里粘贴 [API 密钥](https://platform.deepseek.com/)，保存。

- 保存后页面看不到明文密钥，这是设计如此。
- 密钥落在本机 `$DSH_HOME/.credentials.yaml`，不是仓库里的文件。
- **不用重启** `dsh web`，下一轮请求就会用新密钥。

其它厂商或公司网关：[配置模型](../../../docs/user/guide/providers.zh.md)。初学只用 DeepSeek 即可。

Windows 上 `$DSH_HOME` 一般在用户目录下（具体以本机安装说明 / 环境变量为准）；不要把凭据文件拷进 Git。

### 第二步：选择工作区

全新 Web UI **不会**自动选中文件夹。输入框在选中工作区之前是不可用的。

1. 点 **选择工作区**。
2. 把你要让 Agent 读写的那个项目目录加进去。
3. 选中它。

`dsh` 启动时所在的目录，是默认的文件系统位置；你仍然要在界面里**显式选中**一个工作区。

### 第三步：开会话、发任务

新建会话，输入例如：

> 用中文概括这个仓库是干什么的，并列出最主要的几个目录。

Agent 可以读文件、改文件、跑命令。需要你批准的操作，页面会先问你。

## 3. 使用时记住的边界

- **网页是给人点的；命令行 headless 是给脚本的。** 两种都是同一套 Harness。
- 改客户端插件源码后，生产模式要重新 `pnpm run build`，再**刷新已有页面**，不要另开一个端口的新服务器却去验旧标签页。
- 不要单独拿 `pnpm run dev:web` 当「完整产品」：完整组合由 `dsh web` 承载。开发热更新是进阶话题，见官方 postmortem / 开发文档，初学可跳过。

- [ ] 已选中一个工作区，输入框可用
- [ ] 发出过至少一条任务，并看到回复或审批提示
