# 课 07 · 官方说的插件是什么，怎么插、怎么写

> [!abstract] 一句话
> 「Everything is a plugin」指运行中的 dsh 整棵能力树都是 Cordis 插件；被认作插件的是能被 Loader 挂上的模块，不是 `.agents/skills` 里的 Skill。

## 图景

官方架构第一句就把产品钉死了：没有一块「不能动的内核」，模型适配、工具表、会话日志、**agent loop 本身**都是插件，所以都可以从配置替换。

被认作插件的，不是某个目录碰巧叫 plugin，而是：**一份模块 + 一行配置**。模块导出框架约定的入口；配置行告诉 Loader「用哪个包、什么 id、什么 config」。Loader 按服务依赖把模块挂到共享的 `ctx` 上。

挂上去之后，插件通过注册工具、提示词段、服务、事件监听来改智能体看见什么、能调什么、中间能不能拦。卸载时这些注册会跟着撤掉。

设置里的「插件」页、Agent 预设、`.agents/skills` 的 Skill，都不是这一课里的「插件」本身。

## 步骤

### 1. 先把五个容易撞名的东西拆开

| 你听见的 | 官方实际指什么 | 不要当成 |
|----------|----------------|----------|
| **插件**（本课） | Cordis 模块：导出 `apply`，或 `Service` 子类；由 Loader 挂到 `ctx` | Skill 文件夹、npm 随便一个库 |
| **配置行** | `cordis.yml` / `cordis.patch.yml` 里一条：`id` + `name` + 可选 `config` | 插件源码本身 |
| **组合包 bundle** | 带 `dsh.bundle` 的 npm 包，里面是一批配置行 + 它们要挂的代码 | 单个插件模块 |
| **profile** | `~/.dsh/profiles/<名>/` 里的具名组装：叠哪些 bundle、树外装了哪些包、用户自己的 patch | 一个会话的预设 |
| **Agent 预设** | 一份 `agent.cordis.yml` 目录，挂到**一个会话**的 Agent 上 | 宿主整棵插件树 |

课 06 已经写过：预设 ≠ 宿主「插件」页 ≠ 权限预设 ≠ 模型页。本课补一句：**Skill**（`SKILL.md`）是给模型读的工作流说明，由技能工具扫目录；**不是** Cordis 插件。

### 2. 用官方原话钉死「Everything is a plugin」

根 [AGENTS.md](../../../AGENTS.md)：

> DeepSeek Harness is a plugin-based agent harness on vendored Cordis: **everything is a plugin**.

架构中文稿 [docs/architecture.zh.md](../../../docs/architecture.zh.md)：

> 产品的每一部分都是插件，包括模型适配器、工具注册表、会话日志，以及 agent loop（智能体循环）本身，因此每一部分都可以从配置替换。
>
> 不存在需要打补丁的特权内核：扩展 dsh 的方式是把插件挂载到其他插件旁边。

人话：你不要去「改内核里的 if」。你写一个旁路插件，注册到已有挂钩上；或者用 patch **整行替换**某一条已有配置。本叠加仓还加了一条：能插行就不改官方包，禁止先改 `agent-loop`。

入门定义更短，见 [docs/user/develop/basic/index.zh.md](../../../docs/user/develop/basic/index.zh.md)：

> 在 Harness 中，插件是一个导出 `apply` 函数的 TypeScript 模块。框架在加载时调用 `apply`，传入一个 `ctx`。

入门页后文立刻补了对象形式和类形式。完整判定见下一步。

### 3. 什么样才算插件：代码格式

底层框架是仓内 vendored 的 **Cordis**。[docs/cordis-primer.md](../../../docs/cordis-primer.md) 五条里的第一条：

> A plugin is a object that implements Service. It can be a function with optional `inject` and `apply(ctx)` fields, or a `Service` subclass whose lifecycle Cordis mounts into the current context.

官方用户教程归纳成三种形态（同一页）：

**函数形式（最常见的工具插件）** —— 具名导出，**不要**再加 `export default`：

```ts
import type { Context } from '@deepseek-ai/cordis'

export const name = 'hello-plugin'
export const inject = ['tools'] // 可选；需要 ctx.tools 时再写

export function apply(ctx: Context) {
  // 依赖已就绪；在这里注册能力
}
```

需要用户可调参数时，再导出同名的 TypeScript 类型和 **Schemastery** `Config`（不能是普通对象），见 [docs/user/develop/basic/config.zh.md](../../../docs/user/develop/basic/config.zh.md)。

**对象形式** —— `export default { name, inject, apply }`。

**类形式** —— `export default class X extends Service`，在构造函数里 `super(ctx, 'myService')`，向别人提供 `ctx.myService`。

仓内硬规则（[packages/AGENTS.md](../../../packages/AGENTS.md)）：服务包默认导出 Service 类；函数插件具名导出 `name` / `inject` / `Config` / `apply`，**没有 default export**。两种混在一个模块里，Loader 会丢掉函数插件的 `inject`（事故见 [docs/postmortem/0001-acp-default-export-drops-inject.md](../../../docs/postmortem/0001-acp-default-export-drops-inject.md)）。

仅有这些导出还不够进运行树。还要有人写出配置行，并且 `name` 能被 Node 解析到这份模块。

### 4. 配置行格式：怎么「插进去」

一行最少长这样：

```yaml
- id: hello
  name: '@deepseek-ai/dsh-tool-todo'
  config:
    allowParallelInProgress: false
```

| 字段 | 作用 |
|------|------|
| `id` | 这一行在整棵树里的稳定名字。后面的 patch **按 id 整行替换** `config`，不和上一层做字段合并 |
| `name` | 要加载的模块：npm 包名、相对/绝对路径，或官方教程里的绝对 `.ts` 路径 |
| `config` | 交给该插件导出的 `Config` 做校验和填默认 |

官方内置树不是手写一份巨无霸 `cordis.yml`，而是空列表上叠层。顺序见架构文：

1. profile 列出的每个 **bundle**（先 `dsh-base`，再 `dsh-web-app` 或 `dsh-headless`）
2. 该 profile 自己的 `cordis.patch.yml`
3. Harness home 根上那份 `cordis.patch.yml`
4. 启动时的 `--patch` 覆盖

`insert` 加新行；按 `id` 的 patch 替换已有行的整份 `config`。行顺序**不**决定加载先后；谁先 ACTIVE，看 `inject` 声明的服务齐了没有（[docs/user/develop/framework/index.zh.md](../../../docs/user/develop/framework/index.zh.md)）。

本机实际挂了什么，官方让你看：

```sh
pnpm dsh --profile web --dump-config
```

打印出来的每一行，都可以被你自己的 patch 换掉。

### 5. 存在哪、怎么存、怎么取、怎么读

**仓内官方插件（观摩用）**

| 位置 | 放什么 |
|------|--------|
| `packages/<组>/<包>/` | 一个 `@deepseek-ai/dsh-<名>` 工作区包 = 通常一个插件（或缝的一角） |
| `packages/<组>/<包>/src/index.ts` | 入口：`apply` 或 `export default class … extends Service` |
| `packages/bundle/base/cordis.patch.yml` | 每个 profile 的第一层：把包名插成配置行 |
| `packages/bundle/web-app/cordis.patch.yml` | 网页脸多出来的行 |
| `packages/bundle/headless/cordis.patch.yml` | 无界面一次性运行多出来的行 |
| `vendor/cordis/` | 框架本身；不要当业务插件改 |

例如待办工具：代码在 [`packages/todo/tool-todo/src/index.ts`](../../../packages/todo/tool-todo/src/index.ts)（`export const name = 'tool-todo'`，`inject = ['tools']`）；组装行在 base patch 的 `id: tool-todo`，`name: '@deepseek-ai/dsh-tool-todo'`。

**本机用户侧（跑起来之后）**

| 位置 | 放什么 |
|------|--------|
| `~/.dsh/profiles/<名>/` | 该 profile 的 `package.json`（`dsh.profile` + 树外依赖）和 `cordis.patch.yml` |
| `~/.dsh/profiles/node_modules/` | 启动时补齐的扁平链接，让配置行里的裸包名能按 Node 规则解析 |
| `~/.dsh/cordis.patch.yml` | home 级 patch，压过 profile 那份 |
| `dsh plugin --profile <名> add <包>` | 把可安装 bundle 写进该 profile（官方发布教程） |

**取和读（启动时）**

1. `app-boot` 读 profile，按层合成条目列表（机制见 [packages/boot/app-boot/README.md](../../../packages/boot/app-boot/README.md#profiles)）。
2. Loader 看每一行的 `name`，按 Node 解析模块（包名走上面的 `node_modules`；官方入门课的 scratch 插件要求**绝对路径**，因为 patch 不会改 Loader 的解析根）。
3. 读到模块后，等 `inject` 里的服务都在 `ctx` 上，再跑 `apply`（或构造 Service）。状态：`PENDING → LOADING → ACTIVE`（失败则 `FAILED`）。
4. 裸插件名还必须出现在解析清单的 `dependencies` 里，仓内门禁 `verify-cordis-config` 会查。

**会话级另一条线（课 06）**

`apps/cli/config/agent-presets/<id>/agent.cordis.yml` 是**挂到某个会话 Agent 上**的小树，不是替换整份 `dsh-base`。同一进程里，宿主插件树和会话预设树同时存在。

### 6. 它怎样改智能体的「最终结果」

插件不直接「改模型」。它改模型**请求前后**的材料，以及工具能不能跑。

| 你想改的结果 | 官方挂钩（架构表） |
|--------------|-------------------|
| 模型从哪来 | 在 `ctx.llm` 注册适配器 |
| 模型能调用哪些工具 | `ctx.tools.register`；schema 会进提示词组装 |
| 某一会话能力不同 | 组装 Agent 预设；需要隔离的服务行加 `isolate` |
| 系统提示多一段 | `ctx.systemPrompt` 注册段落 |
| 拦或改某一步请求 | 听 `agent/pre-step`、`agent/request`、`tools/pre-execute` 等 waterfall |
| 人不用模型就能跑的命令 | `ctx.commands` |
| 换文件系统 / 沙箱 | `ctx.fs` / `ctx.sandbox` 的 Provider |

一次对话的骨架（同一份架构文）：开 turn → 拼提示词和工具表 → `agent/pre-step` → 调模型 → 工具流水线 → 再决定要不要下一步。每一步上的监听器都是别的插件挂上去的。

两条会改「模型看见什么」的铁律：

- **模型可见 ⟺ 已入会话日志。** 新的模型可见输入必须有对应的 session 事件。
- Waterfall 监听必须调用 `next()`，否则下游被短路。

所以：你写的插件若注册了 `greet` 工具，模型请求里就会多一份 schema；模型一旦调用，`execute` 的返回会写成 `tool/result`，再进入下一步。这就是「插进去」到「最终回复」的因果链。官方最小实验：[docs/user/develop/basic/tool.zh.md](../../../docs/user/develop/basic/tool.zh.md)。

### 8. 开发者怎么写一个（官方路径 vs 本仓叠加）

**先做官方入门（学习，不改仓库默认）**

按 [第一个插件](../../../docs/user/develop/basic/index.zh.md)：仓库根建 `scratch-plugin/`，`--patch` 指向绝对路径的 `.ts`，`pnpm dsh web --patch ./scratch-plugin/cordis.yml`。终端出现 `plugin loaded` 即 Loader 认了它。再按 tool 课加一个 `greet`。这只是练习本机，不要把 scratch 提交进官方树。

**本叠加仓要长期留下能力时**

落点是 [20260820-03](../../02-Areas/20260820-03-最佳实践_上游叠加与个性化隔离.md)：`packages/creator/<name>/` + 自有 `cordis.patch.yml` 插行。能插行就不改 `packages/core/**`。先归档再编码（`S-eng-change`），本课不写具体补丁。

**仓内正式包还要满足的格式（对照 cookbook，不是入门 scratch 的最低集）**

- 包名 `@deepseek-ai/dsh-<名>`；`package.json` 的 `main` / `exports` / Cordis peer+dev，见 cookbook §1。
- 每个包有 `./invariant`。
- 注册必须走 `ctx.effect()` / `ctx.on()`，卸载能撤。
- 可调部署值进 `Config`，不要在插件里写死超时之类。
- 无效配置要在加载时响，不要默默跳过。
- 产品可见行为要有真实 `cordis.yml` 的组合测试，不只手挂 `ctx.plugin()`。
- 改了模型或用户能看见的行为，同一 PR 要有无 Key 快照（官方测试政策）。

网页客户端插件另有一套：`dsh.client`、`slots.register`、四份 props。那是 [packages/client/AGENTS.md](../../../packages/client/AGENTS.md)，本课不展开。

### 9. 开发者要注意的问题（本场会踩到的）

- **不要改循环图快。** 新行为挂文档里的扩展点。改 `agent-loop` 必须改架构图，本叠加仓默认禁止当第一刀。
- **函数插件不要 `export default`。** 和类插件的 default 混用会丢 `inject`。
- **`Config` 必须是 Schemastery schema。** 普通对象过不了 Cordis 的 Standard Schema。
- **waterfall 必须 `next()`。** 只观察也要往下传，除非你就是要否决。
- **不要把实现词写进给模型看的 schema / 提示词。** 模型侧只留任务概念。
- **不要把 Agent Skill 目录当成插件热更新。** Skill 被技能工具读取；插件被 Loader 挂载。两者可以同时存在，职责不同。
- **patch 按 id 整份替换 config。** 只想改一个字段也要把该行其余字段重写一遍，否则被你盖掉。
- **空的 `cordis.patch.yml` 会炸。** 官方说空文件或只剩注释解析不成列表；要停用该层写 `[]`。
- **本仓个性化不要改 L1 官方包凑合。** 先 `packages/creator` 或自有 patch。

## 边界

- 本课是 `S-eng-deep`：指出文件、符号、当前行为。不在本场改代码、不合上游。
- 不把 `dsh plugin add`、发布 bundle 写成你今天必须做完的主线；那是官方 `publish` 课，需要时再打开。
- 不讲网页槽位系统、实验包晋级、合 `upstream/master`。
- 命令行只作为 `--dump-config` 和对官方 `--patch` 入门的核对手段，不是产品入口课。

带别人时：先让对方用自己的话说出「模块 + 配置行 + Loader」，再打开 `tool-todo` 和 base patch 对一行，不要一上来背 cookbook 全表。
