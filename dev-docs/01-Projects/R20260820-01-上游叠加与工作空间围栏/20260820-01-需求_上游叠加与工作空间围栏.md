## 目标（Why + What）

- **业务目标**：在官方仍处技术预览、会持续大量提交的前提下，本仓能反复吃进 `upstream/master`，同时个性化功能与默认值不丢、可继续演进。
- **用户价值**：日常用 Pi 与 Cursor 开发时，智能体按同一套含义做事；加功能时少改官方文件；合并日少错、少撕挂钩。
- **成功标准**：
  1. 新个性化默认落在本仓独有路径（或官方扩展点上的新插件/新 bundle），而不是改官方大函数。
  2. 同步日能证明：上游 HEAD 已是祖先、独有路径还在、L3 默认还在、个性化回归绿。
  3. Pi 与 Cursor 读同一份根 `AGENTS.md` 与同一份技能树，不为两个产品各维护一套正文。
  4. 需求、方案、否决项写在 `dev-docs/`，不依赖聊天记录。
  5. **先归档、后执行**：你的提问原话、需求、方案、决策要点已落在该次 `dev-docs/01-Projects/R…/` 之后，才允许改代码、嵌工作区或合上游。

## 非功能需求

- **合并流畅**：枢纽 diff 能用「多了一个具名挂钩 / 一行 patch」描述，而不是整文件重写。
- **预览仓现实**：官方无兼容承诺（`SCHEMA_VERSION` 单调、`SESSION_FORMAT_VERSION` 现为 0）；本仓跟随官方破坏性变更并适配挂钩，不自造并行格式。
- **双智能体**：Cursor 的 `.cursor/rules`、Pi/Claude 的技能发现路径可以不同，**正文只有一份**。
- **安全**：不提交 `.env` / 密钥；`git add` 显式路径，禁止 `add -A`。

## 非目标（Out of Scope）

- 本轮不实现具体产品特性（专家团队、新工具等）。
- 本轮不执行上游 merge，不改业务代码。
- 不把挂钩从官方文件抽成扩展（「减枢纽」单独立项，不和建规范绑死）。
- 不把官方 Agent Notes / 生成目录 / 网站源迁到 `dev-docs/`。
- 不向官方提 PR，除非你另开口。
- 不为 Pi 或 Cursor 各写一套完整规则书。

## 约束

- **技术栈**：官方 Cordis 插件树；profile / bundle / patch 分层组合；pnpm workspace `packages/*/*`。
- **已有事实**：`origin` 为个人 fork，`upstream` 为官方；工作枝 `dev-creator`；官方已有完整 `docs/` 与 `.agents/`。
- **官方红线**：新行为走文档化扩展点；改 `agent-loop` 必须改官方 `docs/architecture.md`（这会使合并变难，默认禁止）。
- **时间**：先归档（提问 / 需求 / 方案 / 决策）并等确认，再嵌工作区或改代码。
