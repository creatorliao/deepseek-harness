## 1. 适用与不适用

**适用**（四条同时成立，本仓均成立）：

1. 有明确上游 `deepseek-ai/deepseek-harness`，要反复 `fetch` + 合入。
2. 将有上游没有的能力或默认值，丢了算失败。
3. 目标是「上游可升级」+「个性化还在」，不是拷贝后永不分叉。
4. 自研以**叠加**为主（新插件、新 bundle、新 patch、少数默认），不是把整棵树改成另一产品。

**不适用**：已决定不再跟上游；只要某一个 hotfix 且不能接受同期破坏性变更；个性化已经是大段改写官方函数且画不出文件边界。

## 2. 方向

本仓是官方 Harness 上的**叠加层**，不是第二份上游源码。官方已把扩展做成插件 / bundle / patch；个性化先用这些扩展点，用尽之前不改内核。

| ID | 原则 |
|----|------|
| G1 | 新能力先落 L2（`packages/creator/**`、创作者 patch、`dev-docs/**`）。官方文件只留短、具名挂钩。 |
| G1-dsh | **能插行就不改官方包。** 优先：新插件 → 自己的 `cordis.patch.yml` 插行/覆盖 → profile / `$DSH_HOME` / `--patch`。禁止先改 `agent-loop` 或官方大文件图快。 |
| G2 | 对齐 `upstream/master` 当前树（一次 merge），不挑 commit 声称已对齐。 |
| G3 | 先归 L1 / L2 / L3 / 枢纽，再选 ours/theirs。禁止整文件凭感觉取一边。 |
| G4 | L3 默认本仓说了算；官方新增能力字段保留接口，不删了再自造。 |
| G5 | 机械冲突用规则+脚本；枢纽按卡缝挂钩。 |
| G6 | 完成 = 祖先 + L2 还在 + L3 还在 + 个性化回归，不是「build 过了」。 |
| G7 | 同步在专用分支验收后再进 `dev-creator`。 |
| G8 | 常驻短；长步骤进 skill / 清单。官方 AGENTS 不改写成叠加手册。 |
| G9 | **先归档、后执行。** 你的提问原话、需求、方案、决策要点写入该次主题夹之后，才允许编码、嵌工作区或 `merge`。禁止只把结论留在对话里。 |

## 3. 所有权模型

```text
L3   产品策略      本仓说了算
L2   叠加模块      本仓独有；误删时整块 ours
枢纽 上游文件+补丁 上游最终逻辑为底，挂钩缝回
L1   上游内核      无挂钩的官方文件；不重排、不顺便格式化
```

**挂钩**：为接通 L2 必须出现在官方文件里的符号（具名函数、bundle 行 `id`、patch 目标、一个字段、一处调用）。旁注写清：这是叠加层、官方逻辑从哪来、为什么不能整文件取上游。

**机械冲突**：`pnpm-lock.yaml`、锁步版本、官方生成目录、changelog。生成物跑官方生成器；lock 用 `pnpm install` 重生；版本/changelog 以上游正文为底再追加本仓条。

活表只放清单，不放 AGENTS。

**禁止动的官方测试夹具**：`examples/**/tests/snapshots/**/AGENTS.md` 等是官方产品测试，不是围栏，不当 L2。

## 4. 工作流

### 4.0 先归档、后执行（F-14 / G9 · 每档活必走）

顺序不可反：

```text
你开口 → 归档四件 → 你确认（Gate-S / 按计划执行）→ 才实施
```

| # | 必须落盘 | 默认路径 | 最低内容 |
|---|----------|----------|----------|
| 1 | **提问原话** | 该主题**同一份**需求文的「提问原话」节 | 日期 + 你当轮原话或等价摘录 |
| 2 | **需求** | `{YYYYMMDD}-{NN}-需求_{主题}.md`（主题仅此一份，只修订不新开） | 目标、In/Out、约束、`@待确认` |
| 3 | **方案** | `{YYYYMMDD}-{NN}-方案_{主题}.md`（默认一份；分题仍在本夹） | 怎么做、落点、禁令 |
| 4 | **决策要点** | 方案 `§决策记录` + `00-README` **决策索引** | 已拍板 / 否决 / 未决；挂钩名或「无挂钩」 |

规格正文进 `dev-docs/02-Areas/`，不进主题夹冒充规格。调查报告与外部参考进 `dev-docs/03-Resources/`，主题夹只链过去。

夹内扁平，文件名 `{YYYYMMDD}-{NN}-{文种}_{标题}.md`（`00-README.md` 除外）。全文见 [SP01](../../02-Areas/SP01-dev-docs目录命名与Git.md)。

**实施**包括：改业务代码、嵌 rule/skill/command、建 `packages/creator/`、`git merge` 上游。四件缺一，智能体必须停，并补档后再问你。

纯笔误、只读调查、按你已确认方案做的机械回写（例如把已拍板的一句抄进 `00-README`）不算「实施」，但仍应能指向已有四件。

v1.1 已有「文档写 `dev-docs/`」和「决策进主题夹」，但未把**你的原话**列为强制件，也未把「先归档」写成实施门闩。v1.2 补齐。

### 4.1 日常：加个性化

1. §4.0 四件已在该次 R 夹；否则先补档，不拉枝改代码。
2. 从 `dev-creator` 拉 `feat/<短主题>` 或 `fix/<短主题>`。不要在同步专用枝上堆功能。
3. 走 §4.3；能 L2 则不碰官方包。
4. 必须接通官方入口：L2 写主体；官方侧只加挂钩或**整行 patch**（patch 替换整份 row config，必须重述保留字段）。
5. 跟上游会撞的决策写入该次 `dev-docs/01-Projects/R…/00-README`。
6. 只 `git add` 自己的路径。创作者包装进 `packages/*/src` 则遵守官方测试 / coverage / invariant，不降标。

### 4.2 同步日：吃上游

| 阶段 | 动作 |
|------|------|
| T0 | §4.0 四件已在同步主题夹；`git fetch upstream` 与 `origin`；记下 `dev-creator`、`upstream/master`、当场 `merge-base`；工作区干净 |
| T1 | 开 `feat/R{日期}-*-sync-upstream`；`git merge upstream/master`。搞砸了 `merge --abort`，不用 `reset --hard`，不 rebase 本仓历史 |
| T2 | 先清机械冲突 |
| T3 | 枢纽按 §4.8 与清单缝挂钩；L2 被删则 `git checkout --ours -- <path>` |
| T4 | `git merge-base --is-ancestor upstream/master HEAD` + 清单上的回归 + 被对撞的官方窄门（不要默认全量） |
| T5 | 更新主题夹停点；未经你说「合回 dev-creator」不合回；未经你说「推 origin」不 push |

**禁止**：cherry-pick 冒充对齐；枢纽整文件 `--theirs` / `--ours`；冲突块里手编 lock/生成物；`git add -A`。

### 4.3 落点决策树（智能体每次改代码前必走）

先归层，再动手。输出给使用者看的第一张表必须是「意图 / 落点 / 层 / 要不要改官方文件」。

| 意图 | 默认落点 | 层 | 何时才能改官方文件 |
|------|----------|----|-------------------|
| 提问原话、需求、方案、决策、WP、Handoff | `dev-docs/01-Projects/R…/`（见 §4.0） | L2 | 永不（除非你说贡献官方文档） |
| 长期规范、清单 | `dev-docs/02-Areas/` | L2 | 永不 |
| 新工具 / 新服务 / 新 UI 插件 | `packages/creator/<name>/` + 自己的 patch 插行 | L2 | 官方入口不够用：只加挂钩或整行 patch |
| 改某官方插件的默认值 | 创作者 `cordis.patch.yml` 按 `id` 整行重述 | 枢纽（patch） | 不改该插件 `.ts`，除非 patch 表达不了 |
| 改组合（web/headless 多插一行） | 创作者 bundle 或 `--patch` / profile | L2 | 不改 `packages/bundle/base` 等官方 bundle，除非只改自己的叠加包 |
| 必须改循环 / 会话格式 / 官方协议 | **停。写主题夹：为何 1–4 不够。等你拍板。** | 枢纽或禁止 | 默认禁止改 `agent-loop`；改则同时要动官方 `docs/architecture.md`（高冲突，单独授权） |
| 官方 bug、你要回馈上游 | 另开枝，不混个性化；文档走官方 `docs/` | L1 | 按官方贡献流程，不走本叠加方案 |
| `vendor/` | 按 `vendor/README.md` 记本地修改 | 枢纽 | 不另发明 sync |

**对使用者说清楚的一句**：能做成新插件就不改官方源码。

### 4.6 双智能体并行

- **正文一份**：根 `AGENTS.md`、`.agents/skills/**`（含将来的 `overlay-*`）。`.cursor/rules` 只做指针。
- **同时开 Pi 与 Cursor 可以**；同一工作区禁止两个会话改同一路径。开干前在主题夹或回复里声明「本会话独占：…」。
- 提交只 stage 本会话路径。禁止 `git add -A` / `git add .`。
- 禁止 `git stash`、`git checkout .`、`git reset --hard`、`git clean -fd`（会踩掉另一会话）。
- Cursor 若发现不了 `.agents/skills/overlay-*`：Windows 用 **目录联接**（`mklink /J`），不要复制正文；不要用普通文件指针冒充联接。

### 4.7 Git 推送分层

| 动作 | 默认 | 要你说的话 |
|------|------|------------|
| 本地 commit | 你明确说「提交」才做 | 「提交 / commit」 |
| `git push -u origin HEAD`（个人 fork，通常 `dev-creator`） | 允许，但仍要你说一次 | 「推到 origin」 |
| 合回 `dev-creator`（从同步枝或 feat 枝） | 禁止自作主张 | 「合回 dev-creator」 |
| `push` / PR 到 `upstream` 或官方 GitHub | 禁止 | 「做成官方 PR」并指定范围 |
| 同步枝未验收就 push | 禁止 | 验收通过后你再说「推 origin」 |

### 4.8 根 AGENTS 枢纽操作卡

根 `AGENTS.md` 是官方文件。叠加短节是补丁，不是 L2 整文件。

同步冲突时：

1. 取 **上游当前全文** 为底（官方章节、命令、约定全部保留）。
2. 把本仓短节按官方插入点缝回（现插在文首介绍之后、Pre-release 之前）。
3. 短节保持 15～25 行，只含硬约束 + 指向 Areas / skill。**短节正文用中文**，不把本仓增量译成英文，也不做成中英对照。
4. **禁止** `git checkout --theirs -- AGENTS.md`（丢掉叠加）。**禁止** `--ours` 整文件（丢掉官方新纪律）。
5. 官方若在同一位置加了新节：短节让位，仍紧贴文首介绍之后，不把官方新节删掉。
6. 官方英文段落保持英文。不要把官方原文翻成中文来「统一文风」。
