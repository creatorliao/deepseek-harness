# 最佳实践：本地环境构建效率

| 字段 | 值 |
|------|-----|
| 日期 | 2026-08-20 |
| 编号 | 20260820-05 |
| 状态 | 现行 |
| 依据 | 2026-08-20 在 `dev-creator` 上冷装：第一次 `pnpm install` 中断；第二次约 3 分 31 秒（`downloaded 0` / `reused 929` / 链接 935 包）；`pnpm run typecheck` 约 4 分钟；`pnpm dsh --help` 约 5 秒 |
| 官方对照 | [docs/development.md](../../docs/development.md)（first-time setup 以 typecheck 为准） |

本文管**本机怎么把环境装到能干活**，不管官方 CI、不管贡献官方文档。目标是：同一台机器上，第二次不要再付第一次的全价。

---

## 1. 先想清楚：你要哪种「就绪」

官方教程把「安装完成」定义成 `pnpm run typecheck`。那条命令会做整仓 Host `tsc` + Host `tsdown`（含 Typert）+ Client `tsc`，和「CLI 能不能启动」不是一回事。

| 目标 | 要跑什么 | 冷启动大约 | 热启动大约 |
|------|----------|------------|------------|
| A. 能开发 / 能跑 `dsh` | `pnpm install` + `pnpm dsh --help` | 安装数分钟 + 帮助数秒 | 安装秒级 + 帮助数秒 |
| B. 对齐官方 first-time setup | A 完成后再 `pnpm run typecheck` | 再加约 4 分钟 | 增量编译，通常短于冷构建 |
| C. 要 Web 产物 / 已构建冒烟 | B 或单独 `pnpm run build` | 比 B 更长 | 按改动面 |

**默认走 A。** 只有明确要「和官方贡献者教程对齐」或要改 Host/Client 类型图时才走 B。不要把 B、C 绑进「重建环境」。

`pnpm dsh` 走的是 `node --import tsx/esm apps/cli/src/bin.ts`，读源码，不依赖完整 Client 产物。

---

## 2. 怎么想（根因，不是感觉）

本仓慢，通常不是淘宝源没配好。

1. **链接贵，下载往往不贵。** 冷装时 store 里已有包，进度仍会在 `added 0 → 900+` 停很久：Windows/NTFS 上给 245 个 workspace、约 935 个包建 junction/hardlink。
2. **中断最贵。** 链接做到一半停掉，下一轮几乎整段重来。
3. **typecheck 贵在整仓 Host 构建。** 日志里一批包同时 `Build complete in ~36s`，`dsh-typert-generator` / `tsdown:deps` 是大头。
4. **删 `node_modules` 等于自愿回到冷链接。** store 还在也救不回那几分钟的文件系统工作。
5. **杀毒扫描会把链接再乘一档。** 实时扫描 `node_modules` 时，同样 935 个包会再拖长。

Linux 专用 `landlock-run` 平台警告、部分 demo 在 `lib/bin.js` 尚未生成时的 `.EXE` 链接警告，**不是失败**，不要据此重装。

`corepack enable` 若因无法写 `C:\Program Files\nodejs\yarn` 报 EPERM：只要 `pnpm --version` 已是仓库锁定的 `11.7.0`，不必再折腾 Corepack。

## 3. 怎么做（操作顺序）

### 3.1 每次动手前先看三件事

```text
node -v          # 要 ^22.19 或 >=24
pnpm --version   # 要对上 package.json 的 packageManager（现为 11.7.0）
pnpm config get registry
```

国内默认用 `https://registry.npmmirror.com/`。已是该源就不要再改项目级 `.npmrc`（官方仓一般不提交镜像配置）。

再看工作区：已有健康的 `node_modules` 就**不要**先 `rimraf` 再装。

### 3.2 目标 A：能跑

```sh
pnpm install
pnpm dsh --help
```

`install` 退出码为 0 即成功。帮助打出 `Usage: dsh` 即 CLI 可用。

带密钥的真实任务另说：`pnpm dsh --profile headless "任务"` 需要 `DEEPSEEK_API_KEY`，不作为「环境装好」的门槛。

### 3.3 目标 B：官方就绪

只在 A 已绿之后：

```sh
pnpm run typecheck
```

不要和「我只是想跑一下」捆在一起。

### 3.4 必须全量重装时

只在这些情况才清树再装：依赖图坏了、lockfile 大变且 install 报错、或你明确要复现干净克隆。

1. 一次跑完 `pnpm install`，**不要中断**。
2. Windows：把本仓库目录（至少 `node_modules`）加到 Defender / 其它杀毒的排除列表。
3. 保留全局 pnpm store，不要顺手 `pnpm store prune`（除非磁盘真不够）。
4. 重装后先做 A，再按需做 B。

---

## 4. 智能体必须遵守

下次有人说「重建环境 / 装依赖 / 确保能跑」：

1. 先探测：Node、pnpm、registry、是否已有 `node_modules`、当前分支。
2. 默认目标 A。未经点名不要跑 `typecheck`、`build`、`test:coverage`、全量 `test`。
3. `pnpm install` 已在跑就等它结束，不要并行再开一个、不要建议用户取消。
4. 用淘宝源（若当前不是国内可访问的源）。不要为换源改官方会提交的文件，除非被要求。
5. 把平台警告、未构建 demo bin 警告解释为预期，不要当成要重来的故障。
6. 结束后用一张表写清：跑了哪些命令、哪种就绪、下次热路径是什么。

## 5. 检查表（下次对照）

动手前

- [ ] 已区分目标 A / B / C
- [ ] `node_modules` 还在就先增量 `pnpm install`，不先删除
- [ ] registry 已是可用国内源或明确要用的源
- [ ] 预留足够时间一次跑完 install，不准备中途停

进行中

- [ ] 只开一轮 `pnpm install`
- [ ] 进度停在 `added N` 且 `downloaded 0` 时当作链接，不是死锁
- [ ] 不把 landlock / demo `.EXE` 警告当失败

收尾

- [ ] 目标 A：`pnpm dsh --help` 退出 0
- [ ] 只有被要求时才跑 typecheck / build
- [ ] 没有为「更干净」去 prune store 或删依赖树

---

## 6. 为什么这样做是对的

- **把「能跑」和「类型图编过」拆开**，避免每次为 CLI 付一次整仓 Host 构建。
- **保住链接结果**（`node_modules`）和 **包字节**（store），分别省文件系统时间和下载时间。
- **一次装完** 避免 Windows 上最贵的重复链接。
- **智能体默认走窄路径**，避免会话里「好心」再跑官方全套门。

官方 `docs/development.md` 仍是给贡献者的完整教程。本仓日常叠加开发以本文的目标 A 为准。
