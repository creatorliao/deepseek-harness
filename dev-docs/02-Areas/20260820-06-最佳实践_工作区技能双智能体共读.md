# 最佳实践：工作区技能供 Cursor 与 Pi 共读

| 字段 | 值 |
|------|-----|
| 日期 | 2026-08-20 |
| 编号 | 20260820-06 |
| 状态 | 现行 |
| 依据 | 学堂主题要求：技能创建与后续更新都要两种智能体读得到 |

本文管**本仓自有 Agent Skill 放哪、怎么改**。不管官方 `docs/`，不管把技能发布到个人家目录当唯一真源。

---

## 1. 原则

本工作区同时用 **Cursor** 和 **Pi**。创作者技能必须放在**两种智能体都会扫到的同一棵工作区目录**里，并且只维护这一份。

| 做 | 不做 |
|----|------|
| 新建、更新、改名都发生在 `{工作区根}/.agents/skills/<name>/` | 只写进 `~/.cursor/skills` 或只写进 `~/.claude/skills` 却不回写工作区 |
| 一种智能体改完，另一种打开同一路径就能读到新正文 | 在 `.cursor/skills` 与 `.agents/skills` 各放一份再靠手同步 |
| `name`、目录名、`SKILL.md` 的 `name` 字段三者一致 | 为某一客户端再复制一棵会漂的副本 |

Cursor 与 Pi 在本仓都读 `.agents/skills`（根 `AGENTS.md` 创作者叠加已点名）。不要为「Cursor 看起来更顺」再在 `.cursor/skills` 复制整包。

---

## 2. 怎么想

技能若只装在某一客户端的用户目录，另一边会话看不见，学堂课和叠加规则会两套说法。工作区目录进 Git，才是叠加层上的真源。

更新技能等于改这份真源：触发词、工作流、落点、自包含约束一起改。改完后两种智能体下次打开工作区即生效，不必各装一次。

---

## 3. 怎么做（创建与维护同一套）

1. 路径：`.agents/skills/<技能名>/SKILL.md` 及同目录 `references/`。
2. 创建与大改走工作区已有入口习惯；本仓学堂相关技能维持自包含（规则写在技能目录内，不依赖技能外必读）。
3. 根 `AGENTS.md`「创作者叠加」只加**一句**指针（技能名 + `.agents/skills/...`），细则留本文或该技能自己的 `references/`。
4. 更新 `deepseek-harness-learner` 时：仍只改这一棵目录；触发词继续覆盖「写教程」；落盘规则仍指向学堂夹 `R20260820-02-学习教程`。
5. 更新 `dsh-web-run` 时：仍只改 `.agents/skills/dsh-web-run/`；真正启动只通过 `packages/creator/dsh-web.sh`。
6. 不要把技能正文搬进官方 `docs/`。

技能可以发布到 `~/.agents/skills`、`~/.claude/skills` 等处，方便各客户端随处触发。**学堂课文不是技能的附件**：无论谁问，正文只进 `dev-docs/01-Projects/R20260820-02-学习教程/`，细则在学堂技能 [L11](../../.agents/skills/deepseek-harness-learner/references/L11-多端同落点.md)。

---

## 4. 检查

- [ ] 新技能或本次改动的唯一目录在 `.agents/skills/<name>/`
- [ ] 目录名 = frontmatter `name`
- [ ] 未在 `.cursor/skills` 另存一份会分叉的副本
- [ ] `AGENTS.md` 若提到该技能，链接指向工作区 `.agents/skills/...`
- [ ] Cursor 新开对话与 Pi 新开对话都能只靠工作区读到更新后的 `SKILL.md`
- [ ] 写教程时没有把正文写进家目录技能树或另一份客户端笔记
