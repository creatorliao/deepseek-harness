## 1. 从 Pi 抽出的、与产品无关的成功因素

Pi 仓 2026-08-19 一次 `merge upstream/main` 能同时吃 83 个官方提交并保住自研，复盘写明：**靠的是文件所有权，不是合并当天更认真。**

可原样带到本仓的原则（对应方案 v1.1 的 G1–G8）：

| ID | 原则 | 对本仓的含义 |
|----|------|----------------|
| G1 | 新能力先落独有文件；上游文件只留短、具名挂钩 | 本仓更强：官方自己规定「everything is a plugin」 |
| G2 | 合跟踪枝当前树，不挑 commit | `merge upstream/master`，不 cherry-pick 冒充对齐 |
| G3 | 先归层再选 ours/theirs | 禁止凭感觉整文件取一边 |
| G4 | 产品默认本仓说了算；上游新能力字段要留 | 例如将来的 settings / 诊断 / schema 版本 |
| G5 | 机械冲突与枢纽源码分摊 | 本仓机械面：`pnpm-lock.yaml`、生成目录、版本话术 |
| G6 | 完成看祖先 + 独有路径 + 默认值 + 个性化回归 | 不看「编译过了」 |
| G7 | 同步专用分支验收后再进 `dev-creator` | 半成品不进集成分支 |
| G8 | 常驻上下文短；长步骤进 skill / 清单 | 官方根 AGENTS 已经很长，叠加节必须短 |

Pi 的 Improve 同样适用：枢纽混编会留下结构债；changelog/lock 不要在冲突块里左右各剪一半；减枢纽不要和「建规范」绑在同一次施工。

## 4. 本仓四类所有权（初稿，清单确认后冻结）

```text
L3  产品策略     本仓说了算     个性化默认、功能开关、是否启用某官方行、本仓版本叙事
L2  叠加模块     本仓独有       packages/creator/**、dev-docs/**、overlay-* skill、creator bundle/patch
枢纽 上游文件+补丁 禁止整文件取一边  根 AGENTS.md 短节、pnpm-workspace 约束若要放行 creator 前缀、
                                 必须改的官方 cordis.patch.yml / 官方入口、vendor 本地修改日志
L1  上游内核     上游说了算     packages/**（非 creator）、docs/、.agents/notes、官方 dsh-* skill、
                                 vendor 无日志的源码
```

**挂钩（本仓定义）**：为接通 L2 而必须出现在官方文件里的符号——一次 `ctx.plugin` / bundle 行 id / 一个 patch `id` / 一个具名导出。主体实现仍在 L2。

本仓相对 Pi 的优势：多数个性化可以**零挂钩**（只加插件 + 自己的 `cordis.patch.yml` 插行）。只有「必须改官方已有行的默认值」才进入枢纽。

## 5. 双智能体围栏：怎样才算「一份」

| 资产 | 一份正文放哪 | Cursor | Pi / Claude Code | 禁止 |
|------|----------------|--------|------------------|------|
| 仓库总则 | 根 `AGENTS.md` | 自动读 | 自动读（`CLAUDE.md` 内容为 `AGENTS.md`） | 再写一份 `AGENTS.cursor.md` |
| 官方技能 | `.agents/skills/dsh-*` | 按产品发现；不足则 @ 路径 | `.claude/skills` 已指向此树 | 复制到 `.cursor/skills` |
| 叠加技能 | `.agents/skills/overlay-*`（建议） | 若产品不扫 `.agents/skills`，再加 **符号链接** | 随 `.claude/skills` 指针生效 | 两套 SKILL.md 各改各的 |
| 叠加原则（长） | `dev-docs/02-Areas/` 规范 + 清单 | Read 指针 | Read 指针 | 把 T0–T5 贴进 AGENTS |
| Cursor 专属 rule | `.cursor/rules/overlay-*.mdc` **只做指针**（≤20 行） | alwaysApply / glob | 不读 mdc，靠 AGENTS 短节 | 在 mdc 里复制整份规范 |
| 官方 subtree AGENTS | `docs/`、`packages/` 等 | 进入子树时读 | 同 | 改写成叠加文 |

结论：围栏差异只允许出现在**发现路径**（链接、glob），不允许出现在**规则正文**。

## 6. 风险与反模式

| 风险 | 若发生 | 对策 |
|------|--------|------|
| 把个性化写进官方 `packages/core/**` 或 `agent-loop` | 每次上游重构必冲突 | 先插件/bundle；写不清「为何扩展点不够」不准改内核 |
| 个人 PARA 写进官方 `docs/` | 与生成目录、中英配对、预算门互撕 | AGENTS 已禁止；技能改写到 `dev-docs/` |
| 复制官方 skill 到 `.cursor/skills` | 双份漂移，合并时不知哪份真 | 一份 `.agents/skills` |
| 把个人包塞进 `packages/experimental/` | 与官方实验包抢组、发布族语义混乱 | 独立 `packages/creator/` |
| 根 AGENTS 越写越长 | 官方节 + 叠加节都被略过 | 叠加节保持 15～25 行，细节进 Areas |
| 预览仓 schema 自造并行格式 | 无法吃官方破坏性变更 | 跟随官方版本；L3 只保留默认与开关 |
| 未分类就 `checkout --theirs` | 丢掉 Creator fork 短节或 creator 包 | 同步 skill 门闩 |

## 7. 建议（供方案采用，不是施工授权）

1. **原样采用** Pi 方案 v1.1 的 §1～§8 通用模型（两天流程、四类所有权、部件职责、不重复同一句话）。
