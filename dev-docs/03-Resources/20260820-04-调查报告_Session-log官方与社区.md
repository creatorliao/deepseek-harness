## 2. 官方：为什么要有 Session log

仓内架构页原文要点：Session log 是模型看见的上下文的来源；`deriveMessages()` 从它投影出模型历史；fork、resume、transcript、telemetry、持久化都从这一条流派生。规则是 **Model-visible means logged**——进模型请求的事实必须能从 log 重建，所以新的模型可见输入必须新增 session event，而不是另开旁路。

核对：[docs/architecture.md](../../docs/architecture.md) § Session log；决策记录 [.agents/notes/implemented/architecture/2026-06-11-event-sourced-sessions.md](../../.agents/notes/implemented/architecture/2026-06-11-event-sourced-sessions.md)、[.agents/notes/implemented/architecture/2026-06-14-session-persistence.md](../../.agents/notes/implemented/architecture/2026-06-14-session-persistence.md)。

网页导出的官方理由（Agent Note，不是用户手册）：Trajectory 只给折叠投影，带子代理的会话横跨多份 log，bug 报告需要整棵树的**逐字节原始工件**。因此做成 Host 流式 ZIP，而不是 RPC 拉到浏览器再打包。

核对：[.agents/notes/implemented/feature/2026-08-10-web-session-log-export.zh.md](../../.agents/notes/implemented/feature/2026-08-10-web-session-log-export.zh.md)。

产品包说明：`/export` 只触发浏览器下载，**不进模型历史**，token 为零。[packages/session-query/session-log-export/README.zh.md](../../packages/session-query/session-log-export/README.zh.md)。

公开站点上的子系统页把冷读接口写成 `readSession()` → `SessionLogSnapshot`（header + 经 replay 校验的完整事件）。[Session Query](https://deepseek-harness.github.io/deepseek-harness/en/reference/subsystems/session-query)。

外评文章 [SpringBrand：Everything Is a Plugin](https://springbrand.ai/deepseek-harness) 复述同一条：「模型看见的都记进 append-only log；Trajectory 按来源检视；resume / fork / replay 操作同一条事件流。」这是二次转述，课里标「社区/外评」，不替代架构页。

## 3. 官方工程师怎么用

不是「打开 ZIP 肉眼读完再改产品」，而是把 **同一份 jsonl 当测试真源**：

| 用法 | 入口 | 说明 |
|------|------|------|
| 无 Key 回放 | `pnpm run test:snapshot` + `@deepseek-ai/dsh-llm-replay` | fixture 就是 `<scenario>/session.jsonl`；用 `assistant/chunk` 重建每次 `stream()` |
| 录制 / 刷新 | `DSH_SNAPSHOT=record` / `refresh` | 有 Key 才 record；refresh 无 Key，从已提交脚本重写期望 |
| 冷读校验 | `ctx.sessionQuery.readSession(sessionId)` | 不把会话变 live，只做 replay 校验 |
| Resume / Fork | `ctx.agents.resume` / `ctx.sessions.fork` | 从持久化 log 继续或截前缀开新会话 |

核对：[packages/test-support/llm-replay/README.zh.md](../../packages/test-support/llm-replay/README.zh.md)、[docs/testing.md](../../docs/testing.md)。

用户向 Web 指南**没有**单独的「怎么点 Session log」教程；产品行为写在上述 README 与 Agent Note。

## 4. 社区怎么用（标成社区）

### 4.1 损坏的一份 log 拖垮整站

[Discussion #1473](https://github.com/deepseek-ai/deepseek-harness/discussions/1473)：`~/.dsh/sessions/` 下**一份**损坏的 zstd 头，曾使 `sessionPersistence.list()` 抛错，`workspace` 插件 apply 失败，整个 `dsh web` 起不来。后续修复方向是 `list()` 跳过坏工件并 warn，而不是静默修好那一份。针对性 `load` 仍然 fail-loud。

同类讨论还指向 `#1043` / `#1047` / `#1497` 等：`seq` 缺口、撕坏的尾帧、单帧重压整份明文。

### 4.2 第三方体检：dsh-doctor

[boyin111-1/dsh-doctor](https://github.com/boyin111-1/dsh-doctor) 不是官方包。`--session <log>` 会扫悬挂 `tool_call`、以及与加载器相同的 `seq` 连续性（会先展开 packed chunk 行）。社区用它在「侧边栏 500 / 会话打不开」时定位坏文件。

课里只写「可以先备份再扫」，不写成本仓默认命令。

### 4.3 缺什么

公开 Issues 里几乎没有「我用 Session log 做了某某产品分析」的长文。能核对到的社区用法，主要是 **排障与修损坏**，不是「喂给模型自动改程序」。

## 5. 和本仓网页默认组装的差距

| 说法 | 本仓当前事实 |
|------|----------------|
| 模型可以 `session_search` | `@deepseek-ai/dsh-tool-session-query` 是 **opt-in**；[web-app cordis.patch.yml](../../packages/bundle/web-app/cordis.patch.yml) 只挂了 `session-query-sqlite`，默认不给模型这五个工具 |
| 导出后源文件消失 | 否。`readRaw` + ZIP，无删除接口 |
| SQLite 后端也能导出 | 否。`supportsRawArtifacts: false` 时 HTTP 501 |
