# 存储规则（dev-docs）

个人文档只写本目录。官方 `docs/` 不是 PARA 的任何一层，除非你明确要求贡献官方文档。

本文讲清**存哪、叫什么、先落什么**。细则与 Git 以 [SP01-dev-docs目录命名与Git.md](./02-Areas/SP01-dev-docs目录命名与Git.md) 为准。叠加怎么改代码见 [20260820-03](./02-Areas/20260820-03-最佳实践_上游叠加与个性化隔离.md)，不在本文展开。

## 1. 四层

| 目录 | 放 | 不放 |
|------|----|------|
| `01-Projects/` | 进行中主题的需求、方案、决策、状态 | 长期规格；调查正文；外部原文 |
| `02-Areas/` | 全部项目规格：技术规范、最佳实践、评价标准、参考清单 | 调查报告；单次需求/方案正文 |
| `03-Resources/` | 调查报告、外部参考 | 现行规格；进行中需求/方案 |
| `04-Archives/` | 已停用的整夹 / 整篇（原样迁入，不改名） | 仍在用的规格或主题 |

## 2. 技术规范：有编号，文件名不要日期

`02-Areas` 里的技术规范用规格编号，**不是**主题夹那种日期序号。

```text
SP{NN}-{主题名称}.md
```

| 规则 | 怎么做 |
|------|--------|
| 编号 | `SP` + 两位。按仓内已有技术规范递增。编号是身份，改内容也不改号。 |
| 主题 | 短、能看懂。不必再写 `技术规范_`（`SP` 已表示文种）。 |
| 日期 | **不要**进文件名。成文日、修订日写在文内元数据。 |
| 替代 | 整份作废才迁 Archives；新规范用下一个空号。 |

现行技术规范：

| 编号 | 文件 | 管什么 |
|------|------|--------|
| SP01 | [SP01-dev-docs目录命名与Git.md](./02-Areas/SP01-dev-docs目录命名与Git.md) | 四层、主题夹、命名、调查/归档、Git、留痕 |

下一份新技术规范用 `SP02-…`。禁止再写 `{YYYYMMDD}-{NN}-技术规范_{主题}.md`。

## 4. 主题夹：同主题同夹，夹内扁平

夹名：`R{YYYYMMDD}-{NN}-{主题}/`。日期是**首次建夹日**，之后不改。同一功能或同一问题只进**一个**夹。

夹内一层文件，不建 `实施计划/`、`资料/`、`决策/`。只有单夹超过约 15 个文件、且两类材料从来不会一起打开时，才允许加一层，并在 `00-README` 写明原因。

| 文件 | 规则 |
|------|------|
| `00-README.md` | 固定名。文档索引、决策索引、阶段、停点。 |
| `{YYYYMMDD}-{NN}-需求_{主题}.md` | 该主题全部需求**这一份**，只修订、不新开 `需求2`。提问原话写在本文「提问原话」节。 |
| `{YYYYMMDD}-{NN}-方案_{主题}.md` | 该主题方案**这一份**。修订进原文；分题仍留本夹。决策写在 `§决策记录`，并回链到 `00-README`。 |
| 审查 / 验收等 | `{YYYYMMDD}-{NN}-{文种}_{标题}.md`，与需求/方案平铺。 |

调查不进主题夹，只在 `00-README` 链到 `03-Resources/`。

## 7. 技能写 `docs/` 时改写到这里

| 习惯写法 | 本仓写成 |
|----------|----------|
| `docs/01-Projects/…` | `dev-docs/01-Projects/R…/`（同主题同夹，扁平） |
| `docs/02-Areas/` 技术规范 | `dev-docs/02-Areas/SP{NN}-{主题}.md` |
| `docs/02-Areas/` 其它规格 | `dev-docs/02-Areas/{YYYYMMDD}-{NN}-最佳实践_|评价标准_|参考_{主题}.md` |
| 需求 / 方案进 Areas | 进主题夹，不进 Areas |
| 调查进 Areas 或主题夹 | `dev-docs/03-Resources/` |
| 官方 `docs/AGENTS.md`、`architecture.md`、生成目录 | 只读。不写 PARA |

## 8. 留痕

```text
提问原话 → 需求（一份）→ 方案（一份）→ 决策索引 → 你确认 → 才实施
```

实施包括改业务代码、嵌规则/技能、建创作者包、`merge` 上游。缺一件就停。

## 9. Git（摘要）

集成分支 `dev-creator`。功能 `feat/<短主题>`，修复 `fix/<短主题>`，合上游 `feat/R{日期}-*-sync-upstream`。提交 `type(scope): 为什么`。显式 `git add`，禁止 `add -A`。未让你提交不要 commit。
