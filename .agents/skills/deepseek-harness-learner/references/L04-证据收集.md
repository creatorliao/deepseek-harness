# L04 · 证据收集（优先仓库，再补网）

取证只对着 [L03](./L03-提问增强与callout.md) 的**调查题**。不要拿口语原话当检索式。

## 1. 优先级（不要反）

```text
1. 当前工作区源码与已生成界面文案（词典、README 旁的真实命令）
2. 工作区学堂夹已有课文 / 问答（避免两套说法）
3. 公开文档 URL、GitHub 上游/讨论（补缺口，不覆盖仓库事实）
4. 社区口碑与 issue（标成「社区」，不当成本仓默认行为）
```

仓库里已经写死的命令、默认端口、中文按钮文案，以源码和本机跑通的输出为准。感觉和文档打架时，写「仓库当前行为」，并链到你核对过的符号或文件名（用仓库内相对路径写在**教程**里可以；技能自己的 SKILL 不要链出技能根）。

不要把「上次在另一个智能体里的聊天」或「家目录过期技能副本」当成调查起点。多端时调查路径仍是本表，见 [L11](./L11-多端同落点.md)。

## 2. 仓库怎么取证

按问题收窄，不要通读整仓：

| 问题类型 | 先看什么 |
|----------|----------|
| 怎么启动 | 根 README、CLI 入口说明、实际执行 `pnpm dsh …` 的报错 |
| 界面点哪里 | 客户端设置相关包里的 locales / 中文词典文件；要对着真界面则 Read `dsh-web-run` 把网页跑起来（[L10](./L10-能力路由.md)） |
| 密钥存在哪 | credentials / home-paths 相关包说明或实现 |
| 装依赖 | 根 `package.json` 的 `engines`、`packageManager` |

信息不够时再联网或 `gh` 拉上游讨论。把「仓内事实 / 官方文档 / 社区」在课里分开写，避免揉成一句断言。

## 3. 不够或有疑

- 本机命令失败：把报错关键句写进课（脱敏），并写对策。
- 两种启动路径（npx 发布版 vs 本仓 `build` + `dsh web`）必须拆开，不要混成一条。
- 不要把「目标 A：能跑 `--help`」说成「网页已就绪」。源码网页要构建产物。
- **不要用 AI 生成图当界面证据。** 按钮文案以词典或本机为准；录像里的课件页用 `mp4-tools-master` 抽帧，见 [L10](./L10-能力路由.md)。

## 4. 角色怎么用证据

| 身份 | 多给什么 |
|------|----------|
| 学习者 | 最短可照抄路径、验收框 |
| 开发者 | 命令失败时看哪类文件、和官方 docs 的对照一句 |
| 培训师 | 先讲给别人时的顺序、常见误操作 |
| 产品经理 | 用户旅程、不要暴露的端口/密钥、预览期兼容风险 |
