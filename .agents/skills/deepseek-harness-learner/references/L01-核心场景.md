# L01 · 核心场景（三角色 × 各三场 + 落盘锁）

先定**角色**，再定**该角色下的一场**。场景换了，**板块顺序不换**（§3）。这样换身份不必换一套讲解结构。

初学者与学习者在「把网页用起来」上合并为同一场，不拆两套上手教程。不能合并的（疑问 ≠ 改装 ≠ 深挖特性）各自留场。干活合计 **9 场**。另加横切场 **S-home-one**（技能可部署多处，课文只回本仓）。一次对话只主跑一个干活场；落盘锁每场都生效，只有用户主要在问「写到哪 / 别的智能体问」时才把 S-home-one 当主场。

旧代号仍认：`S-learn-web`→`S-learn-use`；`S-eng-overlay`→`S-eng-change`；`S-teach-write`→`S-train-write`。

## 1. 总表

| 角色 | 代号 | 一句话 | 为何单开（或已合并） |
|------|------|--------|----------------------|
| 学习者 | **S-learn-use** | 网页用到能发第一条任务 | 初学者上手与学习者「先会用」合并 |
| 学习者 | **S-learn-ask** | 某处不懂、有疑问 | 与「用起来」不同：先澄清概念，不重走安装长链 |
| 学习者 | **S-learn-recall** | 自己能复述、对照已有课 | 还不到写给别人的完整学堂课 |
| 工程师 | **S-eng-run** | 源码跑通 / 启动失败 | 与改装不同：先有产物和进程 |
| 工程师 | **S-eng-change** | 改装、扩展某一处 | 叠加层动手，不先改官方循环 |
| 工程师 | **S-eng-deep** | 深入某一特性 | 读代码取证，不默认开改 |
| 培训师 / 产品 | **S-train-write** | 写成学堂课 | 必须落盘：原话、callout、问答、课程表 |
| 培训师 / 产品 | **S-train-lead** | 带别人走同一张验收 | 不新开长课，用已有清单带着做 |
| 培训师 / 产品 | **S-prod-fit** | 嵌进产品 / 教别人时的边界 | 密钥、工作区、审批、预览期、端口 |
| 横切（任何角色） | **S-home-one** | 随处问，只回本仓学堂夹 | 技能部署 ≠ 笔记本；Obsidian 只认这一夹 |

未点名命令行时，九场都不把 CLI 当主线。凡要落盘，先按 [L11](./L11-多端同落点.md) 认工作区。

## 2. 怎么认

| 原话里主要在问 | 代号 |
|----------------|------|
| 网页怎么开、API Key、工作区、第一次对话、我是初学者怎么用 | S-learn-use |
| 这段什么意思、为什么这样、我没懂、和某某有什么差别 | S-learn-ask |
| 我讲得清吗、对照学堂课、帮我复述一遍 | S-learn-recall |
| build、dist、起不来、3080、web-app 报错 | S-eng-run |
| 改装、扩展、个性化、少改官方、落哪、挂钩 | S-eng-change |
| 这个特性怎么实现的、源码在哪、深入看 | S-eng-deep |
| 写教程、学堂、整理成课 | S-train-write |
| 带着同事走一遍、培训现场、按验收勾 | S-train-lead |
| 接到我们产品里、对外教用户、密钥/审批/暴露面 | S-prod-fit |
| 部署到各智能体、随处问、别写到别处、笔记本打不开、Pi 和 Cursor 各写一份 | S-home-one |

一句两件事：先做**此刻**那一场，另一句只写「下一场是 S-…」。

认完仍走 SKILL 工作流；本文件只补每场要点。

## 3. 块顺序（九场共用，锁死）

1. **图景**（不知）：不超过五句。
2. **整理后的问题**（成文则文首 callout；对话里也先说这一句）。
3. **步骤**（做）：可照抄。
4. **边界**：只写本场会踩到的。
5. **验收**：三到五条可勾。带人与自己用**同一张**。
6. **下一步**：点下一个代号或结束。

禁止：一场里夹另一场的长步骤（例如 S-learn-ask 重写整段安装；S-eng-deep 偷偷改循环）。

## 4. 学习者

### S-learn-use · 用起来

**承诺**：Web 能开、Key 能存、工作区能选中、能发一条任务。不承诺改代码。

- 步骤链：依赖（若无）→ 源码则 `build` → `dsh web` → 内测声明 → Key → 选中工作区 → 只读任务。
- 边界：密钥不进对话和 Git；本机回环；Agent 可能改文件。
- 验收：默认地址能开；Key 已配置或能解释环境只读；工作区已选中；发出过任务或能指出卡在哪。
- 下一步：某处不懂 → S-learn-ask；要改仓库 → S-eng-change；起不来 → S-eng-run。

### S-learn-ask · 有疑问

**承诺**：把卡住房的概念用仓库事实说清。不重走 S-learn-use 全文，除非缺的就是启动。

- 步骤链：点名「哪一句没懂」→ 仓库里对应命令/文案/符号 → 用学习者的话重述 → 一个最小对照（做或看一眼界面）。
- 边界：猜测标成猜测；不够再联网，且与仓内事实分开写。
- 验收：用户能用自己的话复述；知道下一步做哪一件。
- 下一步：要动手用 → S-learn-use；要看实现 → S-eng-deep；要写成课 → S-train-write。

### S-learn-recall · 能复述

**承诺**：对照已有学堂课或刚讲过的步骤，自己讲得完。不新开长课（那是 S-train-write）。

- 步骤链：抽出三到五条验收 → 用户不看稿讲一遍 → 漏了补哪一块。
- 边界：不发明第二套步骤。
- 验收：能按序讲完；漏项有名字。
- 下一步：要教别人并落盘 → S-train-write；带人勾清单 → S-train-lead。

## 5. 工程师

### S-eng-run · 跑通 / 启动失败

**承诺**：源码网页或 CLI 帮助能起来，或能根据报错指出缺产物/缺依赖。不在本场改装。

- 步骤链：看报错原文 → 对照「未 build / 帮助能出 / 端口」→ 只做让它跑起来的最小命令。
- 边界：不要为了排错改业务代码。
- 验收：能指出失败句；下一步命令明确；或进程已在默认地址。
- 下一步：要改行为 → S-eng-change；要懂为什么 → S-eng-deep。

### S-eng-change · 改装一处

**承诺**：落点在独有路径还是必须停；先归档再改。不承诺合上游、不先改核心循环。

- 步骤链：归层 → 原话进主题夹 → 落点表 → 确认后改 → 只 add 本会话路径。
- 边界：枢纽禁止整文件取一边；技能只改 `.agents/skills/<name>/` 一份。
- 验收：表与实施一致；是否改官方文件写清。
- 下一步：先搞懂再改 → S-eng-deep；写成课 → S-train-write。

### S-eng-deep · 深入一特性

**承诺**：指出实现落在哪类文件、当前行为是什么。默认不改代码。

- 步骤链：收窄问题 → 仓内符号/词典/README → 不够再 GitHub → 用工程师语言写「现在做什么 / 不做什么」。
- 边界：深挖不是改装；要改就显式切到 S-eng-change。
- 验收：能指出核对过的文件或符号名；行为与猜测分开。
- 下一步：要改 → S-eng-change；给学习者讲清 → S-learn-ask 或 S-train-write。

## 6. 培训师 / 产品

### S-train-write · 写成课

**承诺**：原话、增强问题、课文、问答、课程表在学堂夹对齐。

- 步骤链：先认本仓工作区（[L11](./L11-多端同落点.md)）→ 需求原话 → 增强问题 → 取证 → `教程_`（文首 callout）→ `问答_` → `00-README`。默认 Mermaid（[L08](./L08-可视化.md)）；点名插图/PPT/抽页则 [L10](./L10-能力路由.md)。未点名则成文后**问一次**要不要像素图或讲义 PPT。
- 边界：不写官方文档树；不另开学堂夹；主线默认网页。不在本技能里实现生图或 ffmpeg。不因客户端把课写到技能部署目录。
- 验收：callout 两层；步骤可照抄；对话与夹内一致；L11 §5 落点也过。
- 下一步：课给谁用，在课内点名对应学习者/工程师代号。

### S-train-lead · 带人做

**承诺**：用已有验收清单带着做完。不现场另写一套步骤。

- 步骤链：选已有课或本场清单 → 一人一步 → 按勾选走。现场要讲义或封面时走 [L10](./L10-能力路由.md)，不现场另发明一套出图步骤。
- 边界：卡住则切到 S-learn-ask 或 S-eng-run，不把带人变成新长课。
- 验收：清单勾完或卡点有代号。
- 下一步：要把现场变成课 → S-train-write。

### S-prod-fit · 产品边界

**承诺**：说清嵌进产品或对外教学时不能让用户踩的坑。不在本场做功能开发。

- 步骤链：点名场景（密钥 / 工作区 / 审批 / 端口 / 预览兼容）→ 仓内当前行为 → 给产品/培训的一句「对外怎么说」。
- 边界：不要把密钥写进对话或仓库；不要教人把服务绑到公网再填 Key。
- 验收：边界三条可转述；和「怎么实现」分开（实现走 S-eng-deep）。
- 下一步：要实现 → S-eng-change；要写成对外讲义 → S-train-write。

## 6.1 横切 · S-home-one · 随处问、一处回

**承诺**：技能可以装在家目录和各客户端；课文、原话、问答、课程表只进本仓学堂夹。换智能体打开同一文件，内容同一份。细则 [L11](./L11-多端同落点.md)。

- 步骤链：认工作区根是本仓 → 确认学堂夹在 → 调查只走仓内路径（L04）→ 写入只走 L02 文种与 L07 格式 → 用 L11 §5 勾验收。
- 边界：工作区不是本仓则只口述、不落盘。不把课写进 `~/.agents` / `~/.claude/skills` / 桌面。不为每个客户端复制一份教程。
- 验收：与 L11 §5 同一张。
- 下一步：还要写成课 → S-train-write（锁已生效）；只要确认落点 → 结束。

干活九场一旦写文件，等于已经套上本场，不必再切主场。

## 7. 一致性自检

- 块顺序是不是 图景 → 问题 → 步骤 → 边界 → 验收 → 下一步？
- 有没有把另一场的长步骤塞进来？
- 带人与自己用的验收是不是同一张？
- 角色下三场有没有被压回「只用网页 / 只改装 / 只写课」三个总场？
- 落盘有没有离开学堂夹、写进技能部署目录或某个客户端自己的笔记？
